## Executive Summary

Task **F6-05** hardens all three office deliverable generators (`generate_docx`, `generate_xlsx`, and `generate_pptx`) with shared, fail-closed validation for user-supplied templates and generated office output packages.

The implementation introduces:
1. Pure Node.js OOXML template path and package security inspection routines (`src/industrial/office/template-safety.ts`).
2. Centralized `OfficeTemplateSafetyService` managing template inspection, untrusted template integrity assertions, and pre-finalization output package security validation.
3. End-to-end integration into `DocxGeneratorService`, `XlsxGeneratorService`, and `PptxGeneratorService`, ensuring that neither user-supplied templates nor output artifacts can introduce active content, macro code, external network dependencies, path traversal, or formula injection.
4. Tool boundary confinement in `src/integrations/tools.ts`, enforcing that template paths are strictly confined within authorized agent scopes.

## Architecture & Implementation Details

### 1. Pure OOXML Package Safety Inspector (`src/industrial/office/template-safety.ts`)

- **Strict Template Path Containment (`validateTemplatePath`)**:
  - Rejects null bytes (`\0`), traversal sequences (`..`), absolute Windows drive paths (`C:\...`), and root paths (`/...`).
  - Verifies that file extensions match allowed safe templates:
    - DOCX: `.docx`, `.dotx` (rejects `.docm`, `.dotm`, `.exe`, etc.).
    - XLSX: `.xlsx`, `.xltx` (rejects `.xlsm`, `.xltm`, `.xlam`, etc.).
    - PPTX: `.pptx`, `.potx` (rejects `.pptm`, `.potm`, `.ppam`, etc.).
  - Enforces project boundary containment using `fs.realpathSync` to block symlink and directory junction escapes outside the project root.
  - Verifies that template target exists and is a regular file.

- **Deep In-Memory ZIP Inspection (`inspectOfficePackageBuffer`)**:
  - Verifies valid PK ZIP header (`0x50, 0x4B, 0x03, 0x04`).
  - Scans all internal ZIP entry paths to reject:
    - VBA macros & projects: `vbaProject.bin`, `vbaData.xml`, `vbaProject.signature`, `vba...`
    - ActiveX controls & binaries: `activeX/`, `activeX*.xml`, `activeX*.bin`
    - Embedded OLE objects: `oleObject*.bin`, `oleObjects/`, `embeddings/`
    - Embedded executable scripts: `*.exe`, `*.bat`, `*.cmd`, `*.ps1`, `*.vbs`, `*.js`, `*.sh`
  - Scans relationship parts (`.rels`) to reject:
    - External relationships (`TargetMode="External"`)
    - Remote URL protocol schemes: `http://`, `https://`, `ftp://`, `file://`, `ms-appx:`, `javascript:`, `data:`, `vbscript:`
  - Scans XML document body parts (`word/document.xml`, `xl/worksheets/*.xml`, `ppt/slides/*.xml`) to reject:
    - Embedded OLE objects (`<w:object>`, `<p:oleObj>`, `<a:oleObj>`, `<oleObjects>`)
    - Executable scripts and command patterns (`<script>`, `powershell`, `cmd.exe`, `wscript.shell`)
    - Spreadsheet formula injection in worksheet `<f>` tags (e.g. `=cmd|' /C ...'`, `=DDE(...)`, `=WEBSERVICE(...)`)
    - Malformed XML and illegal XML structures

- **Offline Template & Output Package Validators**:
  - `validateOfficeTemplatePackage(buffer, artifactType)`: Rejects any template containing forbidden active content, macro parts, external targets, or formula injection.
  - `validateOfficeOutputPackage(buffer, artifactType, relativePath)`: Performs rigorous pre-finalization security validation on every generated deliverable buffer before disk commit.

### 2. Centralized Template Safety Service (`src/service/office-template-safety-service.ts`)

- **Methods**:
  - `validateTemplate(templatePath, artifactType)`: Validates template path and verifies package content offline.
  - `assertTemplateSafety(templatePath, artifactType)`: Throws typed `TemplateSafetyError` on any violation.
  - `assertUntrustedTemplateIntegrity(input, canonicalHash)`: Guarantees that template processing does not alter approval requirements, source hashes, provenance citations, reviewer sign-off, or project scope.
  - `assertOutputSafety(buffer, artifactType, relativePath, auditMeta)`: Validates output package safety before finalization and logs audit events.
- **Privacy-Safe Audit Integration**:
  - Emits `TEMPLATE_VALIDATED`, `TEMPLATE_REJECTED`, `OUTPUT_PACKAGE_SAFETY_VERIFIED`, and `OUTPUT_PACKAGE_SAFETY_REJECTED` audit records.
  - Never logs raw prose, internal text, or secrets; only hashes, part names, and error codes.

### 3. Hardened Generators (`DocxGeneratorService`, `XlsxGeneratorService`, `PptxGeneratorService`)

- **Injected Dependency**: `templateSafetyService: OfficeTemplateSafetyService`.
- **Validation Pipeline**:
  1. Safe industrial output path verification.
  2. Safe template path verification (if `templatePath` is provided).
  3. Strict domain input contract validation.
  4. Security sanitization (reject macro references and dangerous formulas).
  5. Deterministic canonical hash computation.
  6. Mandatory approval verification (`assertValidApproval`).
  7. Untrusted template integrity assertion (`assertUntrustedTemplateIntegrity`).
  8. Source freshness and provenance verification (`verifyFreshnessSync`).
  9. Durable idempotency claim (`idempotencyStore.claim`).
  10. Deliverable generation.
  11. OOXML package format validation (`validateDocxPackage` / `validateXlsxPackage` / `validatePptxPackage`).
  12. Pre-finalization output package safety validation (`assertOutputSafety`).
  13. Atomic artifact finalization (`ArtifactService.finalizeArtifact`).
- **Metadata Registration**: Finalized artifact metadata records `templatePath: normalizedTemplatePath` when a template was applied.

### 4. Tool Boundary & Scope Confinement (`src/integrations/tools.ts`)

- Added optional `templatePath` parameter to JSON schemas for `generate_docx`, `generate_xlsx`, and `generate_pptx`.
- Enforced scope containment in `executeGenerateDocxTool`, `executeGenerateXlsxTool`, and `executeGeneratePptxTool`:
  - If `templatePath` is outside the caller agent's `allowedDirectories`, tool execution fails closed with `UNAUTHORIZED_PATH_ACCESS`.
