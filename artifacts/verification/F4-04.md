## Executive Summary

Task **F4-04** pins a sovereign, local-only Vision-Language Model (VLM) managed under the **Shared GPU Model Manager**, enforcing strict weight ownership, serialized single-model residency, 5-class priority queuing with anti-starvation aging, audited leases, and a 3-iteration stability benchmark.

### Core Industrial Principles Enforced

1. **Pinned VLM Model Profile**:
   - Model: **`Qwen/Qwen2-VL-2B-Instruct`** (`qwen2-vl-2b-instruct-local`)
   - Architecture: `Qwen2VLForConditionalGeneration` (2.21B parameters)
   - Pinned Revision: `aa70c964147048705c93c4e16ff2bc55255470d0`
   - Default Quantization: `int4` (AWQ/GPTQ) for offline sovereign deployment; supports `float16` on CUDA and `float32` on CPU fallback.
   - Resource Budget: Maximum VRAM is pinned at **6144 MiB (6.0 GiB)**, strictly satisfying the NVIDIA GeForce RTX 4060 Laptop hardware constraint (8188 MiB total VRAM, ~6920 MiB idle available).

2. **Shared GPU Model Manager Weight Ownership**:
   - In accordance with Section 4.2 and Gate G4:
     - **Only the Shared GPU Model Manager loads model weights.**
     - **Project services do NOT load weights.**
   - All agent and service requests obtain audited leases against a single shared GPU/VRAM pool.
   - Serialized residency: Exactly one model loaded into VRAM at a time. Switching models safely unloads the resident model once all active leases are returned.

3. **5-Class Priority Queuing & Anti-Starvation**:
   - Priority classes:
     1. Interactive Chat (`interactive_chat`, weight 1)
     2. User-Requested Task (`user_task`, weight 2)
     3. Active Workflow Stage (`active_workflow`, weight 3)
     4. Automatic Workflow Stage (`auto_workflow`, weight 4)
     5. Background Indexing (`background_indexing`, weight 5)
   - 60-second aging: Requests waiting in queue for > 60s improve effective priority by 1 level (capped at priority 2) to eliminate starvation.
   - Fair chat limits: Interactive chat cannot starve background workflows for more than 3 consecutive turns.
   - Cancellable queue requests: Callers can cancel pending queued requests without leaking memory or handles.

4. **Three-Run Benchmark Stability Harness**:
   - Harness executes 3 consecutive benchmark iterations:
     - **Run 1: Cold start**: Measures model cold load initialization (budget <= 45,000 ms GPU / 180,000 ms CPU) and multimodal inference.
     - **Run 2: Warm inference**: Measures execution on resident model (warm switch budget <= 5,000 ms, inference <= 15,000 ms).
     - **Run 3: Repeatability**: Verifies absence of VRAM leaks, drift, or performance degradation.
   - Output hash consistency: Output SHA-256 hashes match across repeated identical multimodal queries, guaranteeing deterministic behavior.

5. **Fail-Closed Negative Guardrails**:
   - `OOM_BUDGET_EXCEEDED`: Models requiring VRAM > 6144 MiB are rejected before allocation.
   - `MODEL_UNHEALTHY`: Failed health probes mark model unhealthy and reject lease requests.
   - `REVISION_MISMATCH`: Any requested or live revision deviating from the pinned revision (`aa70c964147048705c93c4e16ff2bc55255470d0`) fails closed.
   - `NO_RUNTIME_DOWNLOAD`: Missing local snapshot files or attempted network downloads fail closed.
   - `CONCURRENCY_VIOLATION`: Attempting concurrent unqueued GPU residency without a hardware manifest waiver is rejected.
