## Executive Summary

Task **UI1-15** completes the UI1-B phase milestone by delivering a sovereign, strictly read-only Agent Cockpit for observing active and historical multi-agent workflow executions. The cockpit provides an authoritative, topologically sorted Directed Acyclic Graph (DAG) projection, live telemetry, and a deterministic event replay engine.

In strict compliance with the **Zero Ephemeral State Rule**, every indicator, stage status, model residency attribution, tool trace, and latency timing is computed directly from typed persistent state (`.maos/plans/` and `.maos/events/`) and validated through pure domain reducers. No GUI-only state or client-side mutations are permitted.

## Key Capabilities & Architecture

### 1. 12 Authoritative Indicators
Every indicator in the cockpit derives strictly from typed events (`SequencedEvent`) and validated plans (`WorkflowPlan`):
1. **Workflow Stages (DAG)**: Stages, dependencies, and topological progression (`PENDING`, `READY`, `RUNNING`, `COMPLETED`, `FAILED`, `SKIPPED`, `WAITING_APPROVAL`, `INTERRUPTED`).
2. **Active Agent Identity**: Agent attributed to each stage (`assignedAgentId`) and currently executing agent (`activeAgentId`).
3. **Actual Resident Model**: Exact family, revision, hardware target (`cuda`/`cpu`), quantization, and fallback flags (`isFallbackCpu`) leased from the Model Manager.
4. **Tool Executions**: Exact tool name, total invocation counts, execution timestamps, duration in ms, and exit status (`success` vs `failure`).
5. **I/O Artifacts**: Input source IDs, source SHA-256 hashes, expected artifact types, generated artifact IDs, and output content hashes.
6. **Retries & Error Diagnostics**: Retry attempts count, maximum configured retries, last retry reason, error codes, and failure details.
7. **Token Telemetry**: Exact prompt tokens, completion tokens, and total token consumption accumulated across stages.
8. **Latency Timings**: Individual stage duration and total workflow elapsed latency (ms).
9. **Approval Gates**: Approval requirement flag, approval reason, live approval status, reviewer ID, role, and review timestamp.
10. **Monotonic Sequence Cursor**: Authoritative event sequence pointer (`currentCursor`) and total processed event counter.
11. **Run Status & Summary**: Overall run state (`PENDING`, `RUNNING`, `COMPLETED`, `FAILED`, `INTERRUPTED`), start/completion timestamps, and stage counts.
12. **Integrity & Verification Flags**: Deterministic plan hash verification and audit provenance.

### 2. Pure Deterministic Replay Engine (`src/domain/cockpit.ts`)
- **100% Determinism**: Pure functions `createInitialCockpitState`, `applySequencedEventToCockpit`, and `reconstructCockpitState` guarantee that feeding the same event stream produces the exact same immutable state object, verified across 100 consecutive randomized-order replays.
- **Topological Invariant Enforcement**: Only nodes whose upstream dependencies have all reached `COMPLETED` can be promoted to `READY` or `RUNNING`.
- **Replay Scrubber**: Enables users to scrub through historical events or resume from an intermediate cursor without state loss or node duplication.

### 3. Strict Negative Protections
- **No Visual Editing**: The cockpit is strictly a read-only projection. UI elements provide zero drag-and-drop node editing, dependency rewiring, or state overriding.
- **Zero Placeholder Success Badges**: Dependent nodes initialize as `PENDING`; nodes with zero dependencies initialize as `READY`. No stage can display `COMPLETED` without an authoritative `STAGE_COMPLETED` event.
- **Cross-Project Isolation (`CROSS_PROJECT_EVENT_REJECTED`)**: Events originating from a foreign `projectId` are rejected by the reducer and backend service.
- **Out-of-Order / Duplicate Suppression**: Events with sequence numbers less than or equal to the current cursor (`sequence <= cursor`) are idempotently ignored.
- **Phantom Completion Defense**: If a run or stage has encountered `INTERRUPTED` or `FAILED`, subsequent completion events are strictly blocked, preventing false-positive success reporting.

### 4. Authoritative Backend Service (`CockpitService`)
- Implemented in `src/service/cockpit-service.ts` and registered in `ServiceContainer`.
- Authoritatively reconstructs state from disk by querying `WorkflowPlanningService` (`.maos/plans/`) and `AuditService` / `EventStore` (`.maos/events/`).
- Emits confirmed force-stop actions via `ApprovalService.executeForceStop`, terminating running tasks, canceling queued entries, and logging append-only audit records.

### 5. Loopback REST API Router (`/api/v1/cockpit*`)
- `GET /api/v1/cockpit`: Lists active and historical workflow runs with node completion summaries.
- `GET /api/v1/cockpit/:runId`: Reconstructs and returns the authoritative `CockpitState`.
- `POST /api/v1/cockpit/:runId/stop`: Executes a safe cancel or confirmed force-stop (`FORCE_STOP_CONFIRMATION_REQUIRED` if unconfirmed).
- `GET /api/v1/cockpit/:runId/replay`: Returns events from a specified cursor alongside the reconstructed state.

### 6. 4-Way Client Parity & Runtime Validation
Parity is verified across:
1. Direct backend container: `services.cockpit`
2. Backend REST client: `MaosRestClient.getCockpitState`, `listCockpitRuns`, `stopCockpitRun`, `replayCockpitRun`
3. Frontend REST client: `BrowserRestClient` with runtime schema validation (`validateCockpitState`, `validateCockpitRunsList`)
4. GUI Adapter: `GuiApiAdapter.getCockpitState`, `listCockpitRuns`, `stopCockpitRun`, `replayCockpitRun`

### 7. Interactive React View (`src/gui/src/views/CockpitView.tsx`)
- **Run Selector & Summary Ribbon**: Active run dropdown, state badges, model attributions, and live token/latency metrics.
- **Topological Pipeline (DAG)**: Clickable stage cards colored by state, dependency connectors, tool pills, and model tags.
- **Read-Only Stage Inspector**: Detailed panel revealing agent assignment, resident model parameters, tool executions table, I/O hashes, retry counters, approvals checkpoint, and error diagnostics.
- **Live WebSocket Event Stream**: Visual pulse indicator displaying connection state and last sequence number.
- **Deterministic Replay Scrubber**: Controls to scrub and replay historical events step-by-step.
- **Emergency Force-Stop Modal**: High-friction confirmation modal requiring explicit confirmation checkbox to halt runaway workflows.
