## Executive Summary

Task **F8-02** implements the production container execution gateway for **Phase F8: Genuine Code Sandbox and Calculation Traces**, ensuring all Python calculation workloads run strictly inside the verified, pinned offline sandbox container (`maos-sandbox-runner:0.3.0-industrial` with digest `sha256:ceba1e7f48ac10413f0a75f53c062b917b10c6ba0457f1f67e4e30fe33a61f76`).

The implementation establishes a multi-layered security boundary:
1. **Low-Level Container Execution Gateway (`src/industrial/container-runner.ts`)**:
   - Discrete argument-array execution via `child_process.spawn` (`shell: false`, `windowsHide: true`).
   - Zero shell interpolation: scripts, paths, and flags are passed strictly as discrete argument vector elements.
   - Enforced container isolation flags:
     - `--network none`: zero inbound/outbound network or DNS access.
     - `--read-only`: immutable root filesystem (`/` and `/usr` strictly read-only).
     - `--cap-drop ALL`: complete kernel capability revocation.
     - `--security-opt no-new-privileges:true`: forbids privilege escalation or suid binaries.
     - `--user 10001:10001`: runs as non-root `sandboxuser`.
     - `--entrypoint /usr/local/bin/python3`: locks entrypoint directly to the Python interpreter, blocking `/bin/sh` or `/bin/bash` escapes.
     - `--memory 1024m`, `--cpus 2.0`, `--pids-limit 32`: resource limits preventing DoS.
     - Isolated tmpfs mounts for `/sandbox/tmp` and `/tmp` (`rw,noexec,nosuid,size=64m`).
     - Bounded workspace mount to `/sandbox/workspace`.
   - Active streaming byte-count enforcement terminating container if stdout + stderr exceeds 50,000 bytes (`status: 'OUTPUT_LIMIT'`).
   - Hard execution timeout enforcement (default 30s) terminating container and descendants (`status: 'TIMEOUT'`).
   - Signal-based cancellation support via `AbortSignal` (`status: 'INTERRUPTED'`).
   - Guaranteed cleanup: explicit `docker rm -f ${containerName}` on timeout, abort, failure, and normal termination in `finally` blocks, guaranteeing zero container orphans.

2. **Authoritative Application Service (`src/service/sandbox-runner-service.ts`)**:
   - Caller authorization check against `AUTHORIZED_CODE_SANDBOX_AGENTS` (`code_agent`, `coder`, `analyst`, `inspector`, `supervisor`, etc.).
   - Pre-execution image digest verification against authoritative pinned manifest.
   - Fail-closed blocking of host executor (`execute_python`) in Industrial mode.
   - Static script analysis detecting forbidden imports (sockets, HTTP clients) and runtime package installation attempts (`pip`, `apt`).
   - Confinement and path traversal defense (`assertSafeWorkspaceMount`), strictly blocking Docker socket paths (`docker.sock`, `docker_engine`) and cross-project paths.
   - Staging of isolated workspace directories in `.maos/sandbox/runs/<runId>/`.
   - Durable mutation idempotency replay and conflict detection via `DurableIdempotencyStore`.
   - Immutable, tamper-evident audit logging via `AuditService.recordAuditEvent()` recording canonical input and output hashes with zero leaked code or secrets.

3. **API & Service Integration**:
   - REST API endpoints in `src/api/router.ts`:
     - `POST /api/v1/sandbox/execute` (and `/api/v1/projects/:projectId/sandbox/execute`)
     - `GET /api/v1/sandbox/manifest`
     - `POST /api/v1/sandbox/verify-image`
   - Registered in `ServiceContainer` (`src/service/index.ts`) as `sandboxRunner`.
   - Hardened `executePython` in `src/integrations/tools.ts` to block host execution in industrial mode.
