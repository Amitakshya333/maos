## Executive Summary

Implemented **F5-07: Local Knowledge-Base CLI and Service Operations**, exposing full lifecycle management (`build`, `status`, `verify`, `clear`) through both the unified application service layer (`KbService`) and the industrial command-line interface (`maos industrial kb ...`).

All operations route through existing typed domain services (`KbCorpusPolicy`, `KbIngestionService`, `EmbeddingService`, `KbVectorIndexService`, `KbSearchService`), completely avoiding duplication of ingestion, embedding, indexing, or policy logic.

Project root safety is strictly enforced: an explicit project folder containing a trusted physical `.maos/` metadata directory is required. Implicit and explicit scans of the user home directory (`os.homedir()`) are forbidden, and path traversal (`..`), symlinked project roots, and junction escapes are rejected fail-closed.

The four required CLI commands are fully operational:
1. `maos industrial kb build`: Validates corpus policy, discovers and ingests approved documents across configured roots, computes deterministic vectors, builds/rebuilds the bounded vector index, fails closed with `NO_RUNTIME_DOWNLOAD` (exit code 12) if offline embedding weights are missing, and records `KB_BUILD_STARTED`, `KB_BUILD_COMPLETED`, or `KB_BUILD_FAILED`.
2. `maos industrial kb status`: Read-only, idempotent inspection of corpus policy limits, ingestion manifest statistics, embedding model offline readiness, and vector index state (`not_built`, `stale`, `up_to_date`, `empty`, `corrupt`). Strictly privacy-clean with zero leakage of raw document text, raw queries, or secrets.
3. `maos industrial kb verify`: Read-only, idempotent verification of corpus policy schema, ingestion manifest, chunk file provenance on disk, source file content hashes against indexed entries, embedding model snapshot manifests, and vector index schema / entry hashes / cumulative `entriesHash`. Fails closed with stable exit codes on any corruption or staleness. Records `KB_VERIFY_COMPLETED` or `KB_VERIFY_FAILED`.
4. `maos industrial kb clear`: Destructive safety gate requiring explicit confirmation (`--yes` / `confirmed: true`) or safe dry-run preview (`--dry-run`). Strictly confines deletion to generated knowledge-base state under `.maos/kb/` (`vector-index.json`, `ingestion-manifest.json`, `chunks/*.json`, `.tmp*`). Strictly preserves source documents (`docs/`), audit history, and general project configuration (`maos.config.json`). Records `KB_CLEARED`.

Stable numerical exit codes (`KB_CLI_EXIT`) are defined and enforced across both human-readable chalk output and machine-readable JSON envelopes (`--json`).
