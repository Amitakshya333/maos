## Executive Summary

Task **F6-04** implements the `generate_pptx` tool and the underlying `PptxGeneratorService` for creating real, offline, air-gapped, verifiable, editable Office Open XML PresentationML (`.pptx`) presentations directly from validated `OfficePptxInput` domain payloads.

Presentation generation runs 100% locally and offline in pure TypeScript/Node.js using built-in standard libraries (`node:zlib`, `node:crypto`). The implementation requires zero runtime downloads, zero npm dependencies, zero external fonts or templates, and completely eliminates reliance on Microsoft PowerPoint, LibreOffice, headless subprocesses, or shell automation.

## Architecture & Implementation Summary

### 1. Pure Node.js PresentationML Packager & Offline Validator (`src/industrial/office/pptx-packager.ts`)
- **OpenXML PresentationML 16:9 Structures**:
  - Standard widescreen slide canvas (12,192,000 × 6,858,000 EMUs / 13.33" × 7.5").
  - `[Content_Types].xml`: Registers presentation, slide layouts, slide masters, themes, and individual slide content types (`application/vnd.openxmlformats-officedocument.presentationml.presentation.main+xml`, `application/vnd.openxmlformats-officedocument.presentationml.slide+xml`, etc.).
  - `_rels/.rels` & `ppt/_rels/presentation.xml.rels`: Strict internal relationship graph connecting presentation to theme, slide master, and slides with zero external targets.
  - `docProps/core.xml` & `docProps/app.xml`: Standard presentation metadata (title, author, creation timestamp, slide count).
  - `ppt/presentation.xml`: Defines slide list (`<p:sldIdLst>`) referencing each slide part with unique IDs and `r:id` relationships.
  - `ppt/slideMasters/slideMaster1.xml` & `ppt/slideLayouts/slideLayout1.xml` (Title), `slideLayout2.xml` (Content): PresentationML layout definitions.
  - `ppt/theme/theme1.xml`: Industrial theme definitions (Office color palette, fonts, format schemes).
  - `ppt/slides/slide*.xml`: DrawingML shapes (`<p:sp>`) and DrawingML tables (`<p:graphicFrame>`, `<a:tbl>`) with text body (`<a:txBody>`), paragraphs (`<a:p>`), and runs (`<a:r>`).
- **Offline PPTX Validator (`validatePptxPackage`)**:
  - Re-opens the generated ZIP archive and validates PK signature.
  - Verifies presence of mandatory parts: `[Content_Types].xml`, `_rels/.rels`, `ppt/presentation.xml`, `ppt/_rels/presentation.xml.rels`, `ppt/slideMasters/slideMaster1.xml`, `ppt/slideLayouts/slideLayout1.xml`, `ppt/slideLayouts/slideLayout2.xml`, `ppt/theme/theme1.xml`, and all declared slide parts.
  - Rejects macro and executable parts (`.pptm`, `ppt/vbaProject.bin`, `ppt/vbaData.xml`, `ppt/activeX`).
  - Rejects external relationships (`TargetMode="External"` and remote URL schemes).
  - Rejects embedded OLE active objects (`<p:oleObj>`, `<a:oleObj>`, `oleObject.bin`).
  - Rejects script elements and executable command patterns (`powershell`, `cmd.exe`, `wscript`).
  - Verifies XML well-formedness of all XML and `.rels` parts.

### 2. PPTX Generator Service (`src/service/pptx-generator-service.ts`)
- **Mandatory Structured Slides**:
  1. `Title & Metadata`: Project ID, Run ID, Task ID, Author, Model Identity, Generated At, Input Canonical Hash.
  2. `Executive Decision & Formal Verdict`: Prominent status badge (VERDICT: FORMALLY APPROVED / REJECTED), Formal Conclusion Statement, and Approval Metadata box.
  3. `Safety Findings & Compliance Status`: Comprehensive table of all findings (Finding ID, Category, Statement, Observed Value, Threshold Value, Unit, Status badge, Citations).
  4. `Critical Engineering Measurements & Units`: Sensor readings and measurements table (Measurement ID, Parameter Name, Numeric Value, Mandatory Unit, Tolerance, Status, Citations).
  5. `Verified Calculations & Computational Methods`: Computational equations table (Calculation ID, Method/Formula, Inputs Summary, Result Value, Mandatory Result Unit, Verification Method).
  6. `Warnings & Operational Limitations`: Operational warnings box (Severity, Code, Message, Acknowledged By) and System Boundaries / Governing Limitations box.
  7. `Evidence Citations & Source Provenance`: Cryptographic evidence ledger table (Citation ID, Source Path, SHA-256 Digest truncated, Location, Verified Evidence Snippet).
  8. `Reviewer Approval & Professional Sign-off`: Formal authority sign-off card (Professional Engineering Sign-off, Sign-Off Authority, Approval Record ID, Decision Timestamp, Payload SHA-256, Certification statement).
  9. `Model Prose (Unverified — Segregated)`: Isolated generative prose block with prominent safety banner `[UNVERIFIED MODEL PROSE — NOT VERIFIED AGAINST STRUCTURED DATA — REQUIRES HUMAN REVIEW]`.
  10. `Embedded Section Tables`: Dedicated slides dynamically generated for each embedded section table (`section.tables`) with column headers and cell rows.
- **Security & Integrity Guardrails**:
  - Project scope containment: rejects inputs when `input.projectId !== params.projectId`.
  - Safe industrial path validation: rejects traversal (`..`), absolute paths, and non-`.pptx` extensions.
  - Mandatory approval enforcement: requires `input.approval.status === 'approved'`.
  - Anti-tampering check: compares approved `payloadHash` against freshly computed canonical hash of the input; rejects if input was modified after approval (`CHANGED_INPUT_AFTER_APPROVAL`).
  - Approval state validation: checks `ApprovalService` record to ensure approval has not been revoked or rejected (`STALE_APPROVAL`).
  - Dynamic disk freshness: verifies cited source files on disk match citation `sourceHash` (`STALE_SOURCE_HASH`, `SOURCE_FILE_MISSING`).
  - Unit enforcement: rejects measurements without units or calculations without result units (`MISSING_UNIT`).
  - Evidence gate enforcement: rejects unresolved conflicts (`UNRESOLVED_CONFLICT`), quarantined evidence (`QUARANTINED_EVIDENCE`), and unreviewed low confidence (`LOW_CONFIDENCE_UNREVIEWED`).
  - Collision prevention: destination collision without `allowOverwrite: true` throws `ARTIFACT_COLLISION`. Overwrite requires explicit approved approval.
  - Durable idempotency: claims requestId through `DurableIdempotencyStore`; replays cached result on identical parameters; rejects conflicting parameters (`IDEMPOTENCY_CONFLICT`).
  - Atomic finalization: writes to temporary file, syncs to disk (`fs.fsyncSync`), computes authoritative SHA-256 hash, and atomically renames into final destination via `ArtifactService.finalizeArtifact`.
  - Privacy-safe audit events: appends `PPTX_GENERATION_STARTED`, `PPTX_GENERATED`, `PPTX_GENERATION_REJECTED`, `PPTX_GENERATION_FAILED` with cryptographic hashes, IDs, and metadata; zero raw prose.
