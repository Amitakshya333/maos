## Executive Summary

Task **F7-03** implements the deterministic typed workflow planning engine for MAOS. It converts a validated `InferenceResult` and `TaskRequirements` into a structured, versioned `WorkflowPlan` without allowing unrestricted LLM planning to bypass permissions, safety policies, or mandatory human approval gates.

Key capabilities delivered:
1. **Deterministic Typed Workflow Recipes**: Workflows are generated from explicit, auditable step templates rather than open-ended LLM guessing.
2. **Strict Step Typing**: Standardized step types (`INGEST_EVIDENCE`, `RASTERIZE_DOCUMENT`, `RUN_OCR`, `ANALYZE_IMAGE`, `REVIEW_CONFLICT`, `SEARCH_KNOWLEDGE_BASE`, `GENERATE_DOCX`, `GENERATE_XLSX`, `GENERATE_PPTX`, `REQUEST_APPROVAL`, `FINALIZE_ARTIFACT`).
3. **Mandatory Approval Gates**: All Office deliverable plans (`GENERATE_DOCX`, `GENERATE_XLSX`, `GENERATE_PPTX`) and safety-critical execution steps mandate an explicit `REQUEST_APPROVAL` gate before `FINALIZE_ARTIFACT`.
4. **Complete Provenance & Reproducibility**: Preserves `projectId`, `taskId`, `runId`, canonical `inferenceInputHash`, source artifact IDs, source hashes, and evidence references.
5. **100% Deterministic Canonical Plan Hash**: Canonical SHA-256 hash computed over normalized plan content (`planHash`) guarantees identical plans for identical inputs across runs.
6. **Hard Safety & Invariant Enforcement**:
   - Rejects unvalidated or ambiguous inference (`CLARIFICATION_REQUIRED`, `UNSUPPORTED`).
   - Fails closed on quarantined, malware-flagged, or stale/expired evidence.
   - Enforces cross-project boundary isolation.
   - Forbids undeclared tool privilege escalation.
   - Enforces pinned model revision checks (`MODEL_REVISION_MISMATCH`).
   - Rejects cyclic dependencies via Kahn's algorithm DAG cycle detection.
7. **Prompt-Injection Neutralization**: Attached documents, OCR text, and user inputs are strictly treated as data; adversarial instructions embedded in documents cannot alter workflow DAG topology or inject unapproved steps.
8. **Service Layer & Atomic Persistence**: `WorkflowPlanningService` persists plans to `.maos/plans/${planId}.json` with write-temp-then-rename semantics and records privacy-safe audit trail events (`WORKFLOW_PLAN_CREATED`, `WORKFLOW_PLAN_REJECTED`).
9. **Zero Network & Zero New Dependencies**: Fully self-contained, air-gapped implementation.

## Architecture & Implementation Details

### 1. Domain Types (`src/domain/workflow-plan.ts`)

- `WorkflowStepType`: Union of 11 typed step categories (`INGEST_EVIDENCE`, `RASTERIZE_DOCUMENT`, `RUN_OCR`, `ANALYZE_IMAGE`, `REVIEW_CONFLICT`, `SEARCH_KNOWLEDGE_BASE`, `GENERATE_DOCX`, `GENERATE_XLSX`, `GENERATE_PPTX`, `REQUEST_APPROVAL`, `FINALIZE_ARTIFACT`).
- `WorkflowStepStatus`: Step lifecycle (`'PENDING' | 'READY' | 'RUNNING' | 'COMPLETED' | 'FAILED' | 'BLOCKED' | 'AWAITING_APPROVAL' | 'REJECTED'`).
- `WorkflowPlanStatus`: Plan state (`'DRAFT' | 'READY' | 'EXECUTING' | 'COMPLETED' | 'FAILED' | 'REJECTED'`).
- `WorkflowPlanStep`: Strongly-typed execution node with `stepId`, `stepType`, `title`, `assignedAgentId`, `requiredTools`, `dependencies`, `inputs`, `outputs`, `requiresApproval`, `approvalReason`, and `status`.
- `WorkflowPlanProvenance`: Complete lineage metadata capturing `projectId`, `taskId`, `runId`, `inferenceInputHash`, `sourceArtifactIds`, `sourceHashes`, `evidenceReferences`, and `createdAt`.
- `WorkflowPlan`: Root plan structure versioned at `schemaVersion: 1`, containing `planId`, `title`, `intent`, `status`, `provenance`, `requirements`, `steps`, and canonical `planHash`.
- `computeCanonicalPlanHash(plan)`: Computes a deterministic SHA-256 hash over canonicalized plan attributes (sorted step IDs, sorted dependencies, sorted tools, and provenance).

### 2. Domain Validators (`src/domain/validators.ts`)

- `validateWorkflowPlanStep(step)`:
  - Validates `stepId` format and non-empty string.
  - Validates `stepType` against allowed step types.
  - Validates `assignedAgentId`.
  - Enforces `requiredTools` array and string bounds.
  - Validates `dependencies` array.
  - Validates expected artifact outputs (`expectedArtifactTypes.length > 0`).
  - Validates `status` against allowed step statuses.
- `checkStepDependencyCycles(steps)`:
  - Implements Kahn's topological sort algorithm to detect dependency cycles.
  - Validates that all dependency references exist within the plan.
  - Returns `{ hasCycle: boolean, cycleNodes?: string[], missingDependencies?: string[] }`.
- `validateWorkflowPlan(plan)`:
  - Validates `schemaVersion: 1`.
  - Validates plan ID, title, and intent.
  - Validates embedded `requirements` via `validateExtendedTaskRequirements`.
  - Validates `provenance` attributes (`inferenceInputHash` SHA-256 format, project/task/run IDs).
  - Validates that plan contains at least one step.
  - Validates each individual step.
  - Checks for cyclic dependencies and dangling dependency IDs.
  - Verifies canonical `planHash` integrity when present.

### 3. Industrial Workflow Planner (`src/industrial/workflow-planner.ts`)

`WorkflowPlanner` implements the core deterministic planning algorithm:
- **Gate 1: Inference Status Gate**: Rejects unvalidated or ambiguous requests (`CLARIFICATION_REQUIRED`, `UNSUPPORTED`) and returns structured clarification prompts.
- **Gate 2: Evidence Freshness & Quarantine Gate**: Inspects all supporting evidence citations; fails closed if evidence is quarantined, infected, stale, or expired.
- **Gate 3: Cross-Project Isolation Gate**: Confirms request context belongs strictly to target project ID.
- **Gate 4: Requirements Resolution**: Merges task requirements and inference requirements, prioritizing declared task permissions.
- **Gate 5: Non-Degradation Modality Check**: When degradation is not permitted, verifies available fleet agents satisfy all required non-text modalities.
- **Gate 6: Typed Recipe Selection**: Selects deterministic templates based on intent (`multimodal-conflict-review`, `document_ocr`, `image_inspection`, `generate_docx`, `generate_xlsx`, `generate_pptx`, `kb_search`, `kb_ingest`, `code_development`).
- **Gate 7: Tool Escalation & Forbidden Tool Checks**: Rejects plans if any step requests a forbidden tool or attempts privilege escalation outside declared tools (while exempting pipeline system tools `artifact_read`, `artifact_write`, `approval_request`).
- **Gate 8: Eligible Agent Resolution**: Resolves each step to an active, capable agent matching modality, tools, and pinned model revision (`MODEL_REVISION_MISMATCH`).
- **Gate 9: Mandatory Approval Gating**: Ensures all Office deliverables and sensitive operations include an explicit `REQUEST_APPROVAL` step positioned prior to `FINALIZE_ARTIFACT`.
- **Gate 10: DAG Cycle Validation**: Kahn's algorithm cycle check.
- **Gate 11: Provenance & Canonical Hash**: Computes SHA-256 `planHash` and packages complete `WorkflowPlan`.

### 4. Workflow Planning Service (`src/service/workflow-planning-service.ts`)

- `createPlan(input)`: Orchestrates planning, performs schema validation, and saves valid plans atomically to `.maos/plans/${planId}.json` (write to `.tmp` file, fsync, atomic rename).
- `getPlan(planId)`: Reads and parses stored plan from disk.
- `listPlans()`: Lists all saved plans in project directory.
- `auditLogging`: Appends privacy-safe audit records (`WORKFLOW_PLAN_CREATED`, `WORKFLOW_PLAN_REJECTED`) containing `planId`, `intent`, `stepCount`, `planHash`, and error codes, without leaking sensitive source content.

### 5. Router & Orchestrator Integration

- `Router.resolvePlanStepAgent(step, availableAgents)`: Provides standalone resolution for individual workflow steps.
- `orchestrator.ts: buildTaskRequirements(task)`: Converts a `TaskFile` into `TaskRequirements` with extended attributes.
- `orchestrator.ts: planTaskWorkflow(task, inference, agents, projectId, runId)`: Bridges queued tasks to deterministic workflow plans.
