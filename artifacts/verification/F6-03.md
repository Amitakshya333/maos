## Executive Summary

Task **F6-03** implements the `generate_xlsx` tool and underlying `XlsxGeneratorService` for producing real, air-gapped, verifiable, editable Office Open XML spreadsheet (`.xlsx`) workbooks directly from validated `OfficeXlsxInput` domain payloads.

All spreadsheet generation is executed 100% locally and offline in pure TypeScript/Node.js using built-in standard libraries (`node:zlib`, `node:crypto`). The implementation requires zero runtime downloads, zero npm dependencies, zero external fonts or templates, and completely eliminates reliance on Microsoft Excel, LibreOffice, headless subprocesses, or shell automation.

## Architecture & Implementation Summary

### 1. Pure Node.js SpreadsheetML Packager & Offline Validator (`src/industrial/office/xlsx-packager.ts`)
- **OpenXML SpreadsheetML Structures**:
  - `[Content_Types].xml`: Registers workbook, styles, worksheets, and core/app property part content types (`application/vnd.openxmlformats-officedocument.spreadsheetml.sheet.main+xml`, etc.).
  - `_rels/.rels` & `xl/_rels/workbook.xml.rels`: Strict internal relationships mapping workbook to sheets and styles with zero external targets.
  - `docProps/core.xml` & `docProps/app.xml`: Document metadata (title, author, creation timestamp, worksheet names list).
  - `xl/workbook.xml`: Defines sheets collection with unique sheet names, sheet IDs, and `r:id` references.
  - `xl/styles.xml`: Clean SpreadsheetML style sheet providing 7 distinct cell styles (Header, Title, Accent/Verdict, Warning/Limitation, Alert/Fail, Number/Float, Bordered standard).
  - `xl/worksheets/sheet*.xml`: Real worksheet XML with dimension attributes, column widths (`<cols><col min="1" max="1" width="30" customWidth="1"/></cols>`), row records, and cell tags with explicit A1-notation cell references.
- **Formula Injection Defense**:
  - Distinguishes formula cells (`<f>...</f>`) from safe literal values.
  - Verifies formulas against dangerous injection inspection patterns (`cmd`, `exec`, `dde`, `hyperlink`, `shell`, `powershell`, `importxml`, `webservice`).
  - Escapes benign user text starting with `=`, `+`, `-`, `@` by prepending a single quote `'` to enforce plain string rendering in spreadsheet software.
  - Rejects leading control characters (`\t`, `\r`) in string fields.
- **Offline XLSX Validator (`validateXlsxPackage`)**:
  - Re-opens the generated ZIP archive and validates PK signature.
  - Verifies presence of mandatory parts: `[Content_Types].xml`, `_rels/.rels`, `xl/workbook.xml`, `xl/styles.xml`, and all declared worksheet parts.
  - Rejects macro and executable parts (`.xlsm`, `xl/vbaProject.bin`, `xl/vbaData.xml`, `xl/activeX`).
  - Rejects external relationships (`TargetMode="External"` and remote URL schemes).
  - Verifies XML well-formedness of all XML and `.rels` parts.
  - Rejects prohibited execution commands inside `<f>` tags.

### 2. XLSX Generator Service (`src/service/xlsx-generator-service.ts`)
- **8 Mandatory Structured Worksheets**:
  1. `Summary & Verdict`: Metadata (Project ID, Run ID, Task ID, Schema Version, Created Date, Author, Model ID, Input Hash) and Formal Verdict block with PASS/FAIL badge and Approval reference.
  2. `Findings`: Tabular register (Finding ID, Category, Statement, Severity, Status, Metric, Observed, Threshold, Unit, Citations, Reviewer Correction).
  3. `Measurements & Units`: Engineering measurements register (Measurement ID, Name, Numeric Value, Mandatory Unit, Tolerance, Status, Citations).
  4. `Calculations`: Computational ledger (Calculation ID, Name, Inputs, Method/Formula, Result Value, Mandatory Result Unit, Verification Method, Citations).
  5. `Warnings & Limitations`: Warning alerts (Code, Severity, Message, Acknowledged By) and scope limitations.
  6. `Citations & Provenance`: Cryptographic evidence ledger (Citation ID, Source Path, SHA-256 Digest, Page/Section/Chunk Location, Verified Snippet).
  7. `Reviewer Sign-off`: Human authority sign-off (Approval ID, Status, Decided By, Decided At, Payload Hash, Verdict Statement, Sign-Off Identity).
  8. `Model Prose (Unverified)`: Clearly segregated model prose blocks with prominent safety disclaimer `[UNVERIFIED MODEL PROSE — NOT VERIFIED AGAINST STRUCTURED DATA — REQUIRES HUMAN REVIEW]`.
- **Dynamic Embedded Section Tables**:
  - Automatically extracts section embedded tables (`section.tables`) and creates dedicated worksheets (e.g., `Table_calib_points`) with typed headers and formatted data rows.
- **Security & Integrity Guardrails**:
  - Project scope containment: rejects inputs when `input.projectId !== params.projectId`.
  - Safe industrial path validation: rejects traversal (`..`), absolute paths, and non-`.xlsx` extensions.
  - Mandatory approval enforcement: requires `input.approval.status === 'approved'`.
  - Anti-tampering check: compares approved `payloadHash` against freshly computed canonical hash of the input; rejects if input was modified after approval (`CHANGED_INPUT_AFTER_APPROVAL`).
  - Approval state validation: checks `ApprovalService` record to ensure approval has not been revoked or rejected (`STALE_APPROVAL`).
  - Dynamic disk freshness: verifies cited source files on disk match citation `sourceHash`.
  - Collision prevention: destination collision without `allowOverwrite: true` throws `ARTIFACT_COLLISION`. Overwrite requires explicit approved approval.
  - Durable idempotency: claims requestId through `DurableIdempotencyStore`; replays cached result on identical parameters; rejects conflicting parameters (`IDEMPOTENCY_CONFLICT`).
  - Atomic finalization: writes to temporary file, syncs to disk (`fs.fsyncSync`), computes authoritative SHA-256 hash, and atomically renames into final destination via `ArtifactService.finalizeArtifact`.
  - Privacy-safe audit events: appends `XLSX_GENERATION_STARTED`, `XLSX_GENERATED`, `XLSX_GENERATION_REJECTED`, `XLSX_GENERATION_FAILED` with cryptographic hashes, IDs, and metadata; zero raw prose.
