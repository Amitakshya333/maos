## Executive Summary

Implemented **F5-04: Bounded Local Knowledge-Base Vector Index**, completing the offline vector storage and lifecycle management component of the MAOS local knowledge base connector. 

The index persists validated chunk embeddings from F5-03 together with document chunk provenance from F5-02 in a project-isolated file under `.maos/kb/vector-index.json`. The persistence engine implements crash-safe atomic writes via temporary files (`.maos/kb/.tmp/index_<timestamp>_<rand>.tmp`), `fsync` flushing, and atomic renaming. Any interruption before final atomic rename leaves zero corrupted or partially-written index files on disk.

Tamper-evidence is enforced through canonical sorting, SHA-256 chunk entry hashing (`computeEntryHash`), and cumulative `entriesHash` verification (`computeEntriesHash`). Any vector value corruption, deleted entry, reordered entry, or metadata tampering causes `loadIndex` to fail closed immediately (`HASH_MISMATCH` or `CORRUPTED_INDEX`) and record an `INDEX_REJECTED` audit event.

Resource limits are strictly enforced: maximum 1,000 documents, 10,000 chunks, 50 MB total vector bytes, 50 MB serialized file size, and batch processing bounded at 32 chunks per call. Stale index states (source file hash change, document version increment, added/removed documents, or corpus policy version change) are cleanly detected and trigger deterministic rebuilds. Prompt-injected or quarantined documents are excluded from indexing. Missing offline embedding weights fail closed with `NO_RUNTIME_DOWNLOAD`.
