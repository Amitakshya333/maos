## Executive Summary

Task **F7-01** implements the extended task requirements schema, queue serialization/parsing, backward compatibility migrations, and strict non-degradation enforcement authority for MAOS.

This provides the foundational requirements layer for Phase F7 (model routing and explicit agentic workflow), extending tasks across:
1. **Modality Requirements**: Explicit typed support for `text`, `vision`, `multimodal`, `embedding`, `code`, and `audio` modalities.
2. **Model Requirements**: Explicit specifications for minimum context window tokens, model family, architecture, required frozen revision, parameter tier (`light`, `standard`, `flagship`), device preference (`cpu`, `cuda`, `metal`, `any`), and quantization level (`q4_k_m`, `q8_0`, `fp16`, `fp32`, `none`, `any`).
3. **Tool Requirements**: Explicit lists of required tools (e.g. `ocr_page`, `generate_docx`), optional tools, and forbidden tools.
4. **Input Requirements**: Input artifact types, MIME types (e.g. `application/pdf`, `image/png`), schema ID, and maximum size limits.
5. **Output Requirements**: Expected artifact types (e.g. `docx`, `xlsx`, `pptx`, `report`), schema ID, and format enforcement.
6. **Negative Requirement Enforcement**: An unknown required capability or unsupported modality/tool/model MUST NOT degrade silently to text-only; it fails closed, eliminating ineligible agents or failing routing when no compliant candidate exists.
7. **Queue Frontmatter & Storage Compatibility**: Atomic YAML frontmatter serialization in `.maos/queue/pending/`, lossless parsing, and seamless backward-compatible migration for legacy tasks.

## Architecture & Implementation Details

### 1. Domain Schemas (`src/domain/schemas.ts`)

- Added canonical types and literal union constants:
  - `TaskModality`: `'text' | 'vision' | 'multimodal' | 'embedding' | 'code' | 'audio'`
  - `TASK_MODALITIES`: readonly array of 6 valid modalities
  - `TaskModelParameterTier`: `'light' | 'standard' | 'flagship'`
  - `TaskDevicePreference`: `'cpu' | 'cuda' | 'metal' | 'any'`
  - `TaskQuantization`: `'q4_k_m' | 'q8_0' | 'fp16' | 'fp32' | 'none' | 'any'`
  - `TaskModelRequirement`: structured model constraint object
  - `TaskToolRequirement`: explicit tool constraint object
  - `TaskInputRequirements`: input specification object
  - `TaskOutputRequirements`: output deliverable specification object
  - `ExtendedTaskRequirements`: composite schema object versioned at `schemaVersion: 1`
- Extended domain interfaces:
  - `Task`: added optional `requirements?: ExtendedTaskRequirements`
  - `CreateTaskInput`: added optional `requirements?: ExtendedTaskRequirements`

### 2. Domain Validators & Degradation Guard (`src/domain/validators.ts`)

- `validateExtendedTaskRequirements(input)`:
  - Validates `schemaVersion: 1`.
  - Enforces non-empty `modalities` array containing only valid enum members.
  - Validates `primaryModality` is a valid member and exists in `modalities`.
  - Enforces positive integer bounds on `minContextTokens` and `maxInputSizeBytes`.
  - Enforces enum membership on parameter tiers, device preferences, and quantizations.
  - Validates string arrays for tools and artifacts.
- `canDegradeToTextOnly(requirements)`:
  - Enforces the strict negative requirement.
  - Returns `false` if `allowDegradation !== true`.
  - Returns `false` if non-text modalities are present (`vision`, `code`, `multimodal`, etc.).
  - Returns `false` if specialized tools are required (`ocr_page`, `generate_docx`, etc.).
  - Returns `true` only for pure text tasks where degradation is explicitly authorized.
- `validateTask(input)`:
  - Validates embedded `requirements` when present, accumulating any nested errors into the validation result.

### 3. Industrial Task Requirements Engine (`src/industrial/task-requirements.ts`)

- **Known Capabilities Registry (`KNOWN_INDUSTRIAL_CAPABILITIES`)**:
  - Whitelist of recognized capabilities across modalities, engines, tools, roles, and tech stacks.
- **Non-Degradation Assertion (`assertNonDegradableRequirements`)**:
  - Throws `TaskRequirementDegradationError` with structured details when unknown capabilities attempt silent degradation.
- **Agent Eligibility Evaluator (`evaluateAgentEligibility`)**:
  - Compares task requirements with agent capabilities, supported modalities, allowed tools, and context window limits.
  - Returns `{ eligible, reasons, missingCapabilities, missingModalities, missingTools, contextExceeded }`.
- **Backward-Compatible Migration (`migrateTaskFileToExtended`)**:
  - Automatically migrates legacy tasks lacking extended requirements without data loss.
  - Infers modalities and tools from legacy capabilities.
  - Sets `allowDegradation: false` to ensure fail-closed security.

### 4. Queue Serialization & State Machine (`src/core/queue.ts`)

- `TaskFile`: extended with optional `requirements?: ExtendedTaskRequirements`.
- `buildTaskContent`: serializes extended requirements into standard YAML frontmatter fields (`modalities`, `primary_modality`, `min_context_tokens`, `model_family`, `model_architecture`, `required_revision`, `parameter_tier`, `device_preference`, `quantization`, `required_tools`, `optional_tools`, `forbidden_tools`, `input_artifacts`, `input_mime_types`, `max_input_size_bytes`, `output_artifacts`, `output_schema_id`, `enforce_output_format`, `allow_degradation`).
- `parseTaskFile`: parses extended frontmatter fields losslessly into `ExtendedTaskRequirements`.
- `createTask`: accepts `requirements` and writes atomically using temp-file + rename pattern.
- Lifecycle: `moveToActive` and `moveToDone` preserve extended requirements end-to-end.

### 5. Router Integration & Eligibility Gating (`src/core/router.ts`)

- `TaskRequirements`: extended with `extended?: ExtendedTaskRequirements`.
- `AgentProfile`: extended with `modalities`, `allowedTools`, and `contextWindow`.
- `isAgentEligible(task, agent)`:
  - Evaluates hard eligibility before scoring.
  - If `allowDegradation: false`, agents missing required modalities, tools, capabilities, or context window are marked ineligible.
- `scoreAgent`:
  - Ineligible agents receive an immediate score of `0` with explicit reasoning.
- `route`:
  - Filters candidate pool to eligible agents when `allowDegradation: false`.
  - Fails closed (`return null`) when no candidate satisfies the task's requirements.
  - Validates explicitly targeted agents (`targetAgent`), failing closed if the target is ineligible.

### 6. Application Service Integration (`src/service/task-service.ts`)

- `TaskService.createTask`: maps and forwards `requirements` to core queue creation.
- `toTask`: preserves `requirements` when converting internal `TaskFile` to domain `Task`.
