## Executive Summary

Task **F7-04** establishes a dedicated, auditable planning and enforcement layer for tool execution contracts and approval governance. It converts each typed `WorkflowPlanStep` (from F7-03) into an explicit, deterministic execution contract (`ToolExecutionPlan`) before any tool is run, and strictly evaluates 16+ pre-execution fail-closed security gates.

Key capabilities delivered:
1. **Explicit Tool Execution Contracts (`ToolExecutionPlan`)**:
   - Each step defines: `contractId`, `stepId`, `planId`, `taskId`, `projectId`, `authorizedAgent`, `allowedTool`, `requiredModelRevision`, `requiredInputs`, `expectedOutputs`, `approvalRequirement`, `humanReviewRequirement`, `idempotencyKey`, `resourceBounds`, `auditRequirement`, `status`, and `contractHash`.
2. **5 Explicit Approval Categories**:
   - `NO_APPROVAL_REQUIRED`: Pure read-only, non-destructive queries with no external side-effects (e.g. `search_kb`).
   - `HUMAN_REVIEW_REQUIRED`: Steps requiring human inspector oversight or flagged conflict verification (e.g. `conflict_compare`).
   - `EXPLICIT_APPROVAL_REQUIRED`: Standard write/mutation operations (e.g. standard file generation).
   - `SAFETY_CRITICAL_APPROVAL_REQUIRED`: Code execution, terminal operations, or hazardous tools (e.g. `bash`).
   - `FINAL_ARTIFACT_APPROVAL_REQUIRED`: Final Office deliverable generation (`generate_docx`, `generate_xlsx`, `generate_pptx`).
3. **Pre-Execution Fail-Closed Security Gates**:
   - Authorized agent verification (`UNAUTHORIZED_AGENT`).
   - Tool permission validation (`TOOL_NOT_ALLOWED`, `FORBIDDEN_TOOL`).
   - Approval presence, state, and validity (`MISSING_APPROVAL`, `APPROVAL_NOT_GRANTED`, `INVALID_APPROVAL_HASH`, `STALE_APPROVAL`).
   - Safety-critical dual sign-off (`SAFETY_CRITICAL_APPROVAL_REQUIRED`).
   - Human review validation (`HUMAN_REVIEW_REQUIRED`).
   - Input artifact integrity and quarantine (`MISSING_ARTIFACT`, `QUARANTINED_ARTIFACT`, `SOURCE_HASH_MISMATCH`).
   - Cross-project artifact containment (`CROSS_PROJECT_ARTIFACT_VIOLATION`).
   - Pinned model revision enforcement (`MODEL_REVISION_MISMATCH`).
   - Modality preservation (`MODALITY_DEGRADATION_REJECTED`).
   - Upstream DAG dependency satisfaction (`DEPENDENCY_UNSATISFIED`).
   - Output schema typing (`OUTPUT_TYPE_MISMATCH`).
   - Prompt-injection privilege elevation / approval bypass defense (`PROMPT_INJECTION_REJECTED`).
4. **Durable Idempotency & Replay Engine**:
   - Evaluates idempotency keys against the durable store before execution.
   - Detects exact replays and returns recorded outputs (`IDEMPOTENCY_REPLAY`) without double execution.
   - Detects conflicting mutations under an existing key and fails closed (`IDEMPOTENCY_CONFLICT`).
5. **100% Deterministic Canonical Contract Hash**:
   - Canonical SHA-256 hash computed over normalized contract attributes (`contractHash`), guaranteeing identical contracts across repeated runs.
6. **Service Layer & Atomic Persistence**:
   - `ToolApprovalPlanningService` persists contracts to `.maos/execution-plans/${contractId}.json` with write-temp-then-rename semantics.
   - Appends privacy-safe audit trail records (`TOOL_EXECUTION_CONTRACT_CREATED`, `TOOL_PRE_EXECUTION_VALIDATED`, `TOOL_PRE_EXECUTION_REJECTED`) without raw text exposure.
7. **Zero Network & Zero New Dependencies**:
   - Pure TypeScript, fully self-contained, air-gapped execution.

## Architecture & Implementation Details

### 1. Domain Types (`src/domain/tool-plan.ts`)

- `ApprovalCategory`: Union of 5 explicit approval categories (`'NO_APPROVAL_REQUIRED' | 'HUMAN_REVIEW_REQUIRED' | 'EXPLICIT_APPROVAL_REQUIRED' | 'SAFETY_CRITICAL_APPROVAL_REQUIRED' | 'FINAL_ARTIFACT_APPROVAL_REQUIRED'`).
- `APPROVAL_CATEGORIES`: Readonly constant array of all 5 approval categories.
- `ToolExecutionContractStatus`: Contract lifecycle states (`'DRAFT' | 'READY_FOR_PRE_CHECK' | 'APPROVED_FOR_EXECUTION' | 'REJECTED' | 'EXECUTING' | 'COMPLETED' | 'FAILED'`).
- `ToolExecutionErrorCode`: Strongly-typed error codes for all security violations:
  - `UNAUTHORIZED_AGENT`, `TOOL_NOT_ALLOWED`, `FORBIDDEN_TOOL`, `MISSING_APPROVAL`, `APPROVAL_NOT_GRANTED`, `INVALID_APPROVAL_HASH`, `STALE_APPROVAL`, `SAFETY_CRITICAL_APPROVAL_REQUIRED`, `HUMAN_REVIEW_REQUIRED`, `QUARANTINED_ARTIFACT`, `MISSING_ARTIFACT`, `SOURCE_HASH_MISMATCH`, `CROSS_PROJECT_ARTIFACT_VIOLATION`, `MODEL_REVISION_MISMATCH`, `MODALITY_DEGRADATION_REJECTED`, `DEPENDENCY_UNSATISFIED`, `IDEMPOTENCY_CONFLICT`, `OUTPUT_TYPE_MISMATCH`, `PROMPT_INJECTION_REJECTED`.
- `HumanReviewGate`: Configuration defining `required`, `reviewType`, `minReviewers`, `reviewerRoles`, `rejectionAction`, and `instructions`.
- `ApprovalGate`: Configuration defining `category`, `requiredRoles`, `approvalPayloadHash`, `validityWindowSec`, `justificationRequired`, `allowedOverrides`, and `emergencyBypassForbidden`.
- `ResourceBounds`: Resource constraints defining `timeoutMs`, `maxMemoryMb`, `maxDiskBytes`, and `maxOutputTokens`.
- `AuditRequirement`: Audit logging policies defining `category`, `logInputs`, `logOutputs`, `redactionRequired`, and `complianceTag`.
- `ToolExecutionPlan`: Root contract versioned at `schemaVersion: 1`, containing all execution parameters and canonical `contractHash`.
- `computeCanonicalContractHash(contract)`: Generates SHA-256 hash across sorted, normalized JSON attributes.

### 2. Domain Validators (`src/domain/validators.ts`)

- `validateToolExecutionPlan(plan)`:
  - Validates `schemaVersion: 1`.
  - Enforces string bounds on IDs, keys, and tool names.
  - Enforces enum membership on `status` and `approvalRequirement.category`.
  - Validates `resourceBounds` (`timeoutMs > 0`).
  - Verifies canonical `contractHash` integrity.

### 3. Industrial Tool Approval Planner (`src/industrial/tool-approval-planner.ts`)

- `createExecutionContract(step, plan, options)`:
  - Selects primary tool and assigns authorized agent.
  - Deterministically derives approval category based on tool sensitivity and step requirements:
    - Dangerous execution tools (`bash`, `shell_exec`) -> `SAFETY_CRITICAL_APPROVAL_REQUIRED`.
    - Office artifact generators (`generate_docx`, `generate_xlsx`, `generate_pptx`) -> `FINAL_ARTIFACT_APPROVAL_REQUIRED`.
    - Conflicting analysis or verification steps -> `HUMAN_REVIEW_REQUIRED`.
    - Read-only tools (`search_kb`, `read_file`, `ocr_read`) -> `NO_APPROVAL_REQUIRED`.
    - Other mutating operations -> `EXPLICIT_APPROVAL_REQUIRED`.
  - Configures human-review gates, resource bounds, and idempotency key (`${planId}:${stepId}:${allowedTool}`).
  - Computes canonical `contractHash`.
- `evaluatePreExecution(contract, context)`:
  - Sequentially runs 16 fail-closed pre-execution evaluation gates:
    1. Agent authorization check against fleet profile and allowed tools.
    2. Forbidden tool policy check against plan requirements.
    3. Pinned model revision match against agent runtime.
    4. Modality preservation check against agent capabilities.
    5. Upstream DAG step completion check.
    6. Prompt-injection defense: blocks privileged escalation attempts embedded in untrusted parameters.
    7. Input artifact existence and cross-project isolation checks.
    8. Input artifact content hash verification (disk SHA-256 matches expected).
    9. Input artifact quarantine / infection flag check.
    10. Approval category validation: verifies approved state, required roles, payload hash integrity, and expiration window.
    11. Human review requirement validation.
    12. Durable idempotency check: detects replays or conflicting requests.
    13. Output schema and expected artifact types check.

### 4. Service Layer (`src/service/tool-approval-planning-service.ts`)

- `createContract(step, plan, options)`: Creates contract and persists atomically to `.maos/execution-plans/${contractId}.json`.
- `getContract(contractId)`: Loads contract from disk.
- `listContracts(planId)`: Enumerates all saved execution contracts for a plan.
- `evaluatePreExecution(contract, context)`: Executes pre-checks and records privacy-preserving audit logs (`TOOL_EXECUTION_CONTRACT_CREATED`, `TOOL_PRE_EXECUTION_VALIDATED`, `TOOL_PRE_EXECUTION_REJECTED`).
- Wired into `ServiceContainer` (`src/service/index.ts`).

### 5. Orchestrator & Integrations Parity

- `src/core/orchestrator.ts`: Added `planStepToolExecution` and `verifyStepToolPreExecution`.
- `src/integrations/tools.ts`: Added `verifyToolExecutionContract` adapter.
