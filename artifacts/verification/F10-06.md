# Phase F10-06 Verification: One-Command Judged Run

## 1. Overview & Requirements
- **Goal:** Add one-command judged run flow for MAOS Industrial orchestrating:
  `PREFLIGHT → POLICY → SERVICES → DAG (Ingest → Analyze → Approval → Synthesize) → VERIFY → AUDIT EXPORT`
- **Specification:**
  - Scope: preflight policy services DAG approvals verify audit export, with interactive/manual boundaries documented.
  - Acceptance: one command (`maos industrial run`) plus mandatory confirmations (`--auto-approve --yes`).
  - Negative Requirements: skipped gate/service or failure cannot continue as success.
- **Canary Hash Preservation:** `rust/test.txt` SHA-256 = `1392245502333919f23e58b8f544f12470db3829aabd5336a011e58d2b733435`.

## 2. Implementation Summary

### A. One-Command Judged Runner (`src/industrial/judged-run.ts`)
1. **End-to-End Orchestrated Pipeline:**
   - **Stage 1 (PREFLIGHT):** Validates host boundary status via `IndustrialFirewallRequirementService` and health diagnostics (`runDiagnostics()`) verifying local Rust engine, project initialization, config files, and retry queues.
   - **Stage 2 (POLICY):** Verifies deterministic safety threshold policies (`demo/industrial/safety_thresholds.json`) and parses vibration (4.5 warning / 7.1 critical) and temperature (85.0 warning / 95.0 critical) criteria.
   - **Stage 3 (SERVICES):** Resolves project-scoped service container (`createServiceContainer`) and records genesis audit event (`JUDGED_RUN_STARTED`).
   - **Stage 4 (DAG WORKFLOW):**
     - *4a. Ingest:* Ingests 500-row `turbine_vibration_log.csv`, `maintenance_report.txt`, and CC0-1.0 `turbine_inspection_scan.pdf`, validating on-disk cryptographic SHA-256 hashes.
     - *4b. Analyze:* Deterministically computes overall vibration RMS (`2.63711 mm/s`) and evaluates threshold excursions, issuing an overall verdict of `FAIL` (due to peak vibration 8.3 mm/s and temperature 97.2 °C).
     - *4c. Approval Gate:* Explicit human-in-the-loop gate boundary. Without `--auto-approve`, execution halts with `GATE_REJECTED` (exit code 10). With `--auto-approve`, requires explicit confirmation `-y / --yes`, failing with `CONFIRMATION_REQUIRED` (exit code 4) otherwise. Authorized human decision (`lead` / `engineer`) is registered in `ApprovalService`.
     - *4d. Synthesize:* Invokes `DocxGeneratorService.generateDocx` using typed `OfficeDocxInput` with validated citations, measurements, calculations, evidence state, and disclaimer. Produces valid OOXML deliverable (`artifacts/generated/turbine_safety_approval_note.docx`).
   - **Stage 5 (VERIFY):** Verifies cryptographic integrity of the deliverable signature and audits the hash chain using the native Rust engine (`services.audit.verifyChain()`).
   - **Stage 6 (AUDIT EXPORT):** Records `JUDGED_RUN_COMPLETED` audit event, seals the run record, exports complete sovereign audit bundle (`artifacts/generated/judged-run-audit-export.json`), and computes canonical SHA-256 digest.

2. **Negative Invariants & Boundary Defenses:**
   - Zero mock bypass of `ServiceContainer`.
   - Halts immediately on preflight failure with `PREFLIGHT_BLOCKED` (exit code 3).
   - Halts immediately on policy/threshold failure with `POLICY_VIOLATION` (exit code 9).
   - Halts immediately on unconfirmed auto-approval with `CONFIRMATION_REQUIRED` (exit code 4).
   - Halts immediately on manual gate without approval with `GATE_REJECTED` (exit code 10).
   - Deliverable generation verifies source hash freshness, units, citations, and anti-tamper constraints via `validateOfficeArtifactInput`.

### B. CLI Integration (`src/industrial/industrial-cli.ts` & `src/cli/index.ts`)
1. **Command:** `maos industrial run`
   - Options:
     - `-p, --project-root <path>`
     - `-d, --demo <name>` (default: `safety-audit`)
     - `--auto-approve`
     - `-y, --yes`
     - `--enforce-firewall`
     - `--json`
   - Exit Codes:
     - `SUCCESS: 0`
     - `INVALID_ARGS: 2`
     - `PREFLIGHT_BLOCKED: 3`
     - `CONFIRMATION_REQUIRED: 4`
     - `RESET_FAILED: 8`
     - `POLICY_VIOLATION: 9`
     - `GATE_REJECTED: 10`
