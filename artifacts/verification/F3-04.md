## 1. Architectural Summary

F3-04 establishes the live event transport and replay boundary between the MAOS core orchestrator and connected user interfaces (CLI, dashboard, and future React GUI).

```
Application Service (Task, Project, Workflow, etc.)
               │
               ▼
   EventStore.writeSequenced() ────► Disk Persistence (.maos/events/events.jsonl)
               │                     (Strict monotonic sequence seq++ assigned)
               ▼
         EventBroker ──────────────► Memory Deduplication & Conflict Check (SHA-256)
        ┌──────┴──────┐
        ▼             ▼
   Subscriber A   Subscriber B     (RFC 6455 WebSocket /api/v1/events)
   [proj=alpha]   [proj=alpha,run=r1]
```

### Core Invariants Enforced

1. **Persistence-First Architecture**:
   - Every event is written and flushed to disk (`.maos/events/events.jsonl`) and assigned a strict monotonic sequence number **before** it is handed to the WebSocket broker for distribution.
   - WebSocket delivery is strictly a live projection adapter, never the authoritative source of truth.

2. **Lossless Replay & Cursor Resumption**:
   - Reconnecting clients pass their last received sequence number as `cursor`.
   - The server queries disk storage starting strictly after `cursor` and transmits missed events in a single ordered batch (`replay_batch`).
   - Subsequent live events resume streaming without duplication (`sequence > lastSentSequence`).

3. **Forward-Gap Detection**:
   - If a client provides a cursor ahead of the server's current latest sequence (`cursor > latest`), the broker immediately sends `{ type: "resync_required", reason: "SEQUENCE_GAP" }` informing the client to resynchronize its snapshot.

4. **Stale-Cursor Detection**:
   - If an event log rotation/pruning causes the oldest retained sequence to advance past the client's cursor (`cursor < oldest - 1`), the broker emits `{ type: "resync_required", reason: "STALE_CURSOR" }` directing the client to perform a full REST snapshot refresh.

5. **Project-Scoped & Run-Filtered Subscriptions**:
   - Clients must subscribe to a valid project hosted by the server. Attempts to subscribe to foreign projects trigger `{ type: "resync_required", reason: "PROJECT_MISMATCH" }`.
   - Optional `runId` filtering ensures clients only receive events pertaining to their target run.

6. **Conflict & Duplication Detection**:
   - The broker verifies incoming event payloads via SHA-256 hashing. Idempotent replays of identical payloads are safe, while conflicting payloads for an existing `eventId` trigger `CONFLICTING_DUPLICATE_EVENT`.

7. **Zero-Dependency RFC 6455 Implementation**:
   - Implemented without third-party packages using standard Node.js `net`, `http`, and `crypto` libraries, preserving 100% offline airgap compliance.
   - Fully supports masked client frames, unmasked server frames, ping/pong heartbeats, and close handshakes.

8. **REST History Fallback**:
   - Exposed `GET /api/v1/events` for environments where WebSockets are unavailable or for initial catch-up queries, supporting `cursor`, `limit`, `projectId`, and `runId`.

## 2. Protocol Specification

### WebSocket Messages: Client to Server

| Message Type | Fields | Description |
|---|---|---|
| `subscribe` | `projectId: string`, `runId?: string`, `cursor?: number` | Subscribe to project stream and request replay from `cursor` |
| `ping` | _none_ | Application-level heartbeat ping |

### WebSocket Messages: Server to Client

| Message Type | Fields | Description |
|---|---|---|
| `subscribed` | `projectId: string`, `latestSequence: number` | Confirms active subscription and announces server sequence head |
| `event` | `event: SequencedEvent` | Live event frame in monotonic sequence |
| `replay_batch` | `events: SequencedEvent[]`, `fromCursor: number`, `toCursor: number`, `hasMore: boolean` | Ordered catch-up batch of missed events from disk |
| `resync_required` | `reason: ResyncReason`, `latestSequence: number`, `oldestSequence: number`, `projectId: string`, `instructions: string` | Signals client state invalidation (stale cursor, gap, project mismatch) |
| `pong` | `timestamp: string` | Response to client application ping |
| `error` | `code: string`, `message: string` | Error notice (e.g., malformed frame, backpressure) |

### REST Endpoint Fallback

```http
GET /api/v1/events?cursor=10&limit=50&projectId=my-project&runId=run-01
```

Response:
```json
{
  "data": [ ... ],
  "meta": {
    "latestSequence": 25,
    "oldestSequence": 1,
    "cursor": 10,
    "count": 15,
    "hasMore": false
  }
}
```
