## Executive Summary

Task **UI1-09** begins Phase **UI1-B** following the successful sign-off of Gate G7. It implements the primary interactive exploration and operational oversight interface for MAOS:

1. **Persistent Conversations under `.maos/conversations/`**:
   - Each conversation is represented as an atomic, schema-validated file (`.maos/conversations/<id>.json`, `schemaVersion: 1`).
   - Mutations (creation, message append, metadata update, and deletion) use safe atomic file writes (`.tmp_*` -> `fsync` -> atomic rename).
   - Strict ID validation prevents path traversal (`..`, slashes, null bytes).
   - Strict project scoping ensures conversations created in Project A are completely isolated from Project B.

2. **Project-Confined Safe Attachments & File Picker**:
   - Files can be inspected and attached exclusively from within the canonical project root.
   - `GET /api/v1/project/files` traverses directory structures while strictly filtering out sensitive and internal directories (`.maos`, `.git`, `node_modules`, `dist`, `.gemini`).
   - Directory traversal attempts in subpaths or attachments (`../`, leading slashes, drive letters, null bytes) fail closed.
   - Attachment sizes are strictly capped at **50MB** (`52,428,800` bytes). Oversized files are rejected immediately with typed code `OVERSIZED_ATTACHMENT`.
   - Maximum 10 attachments per message.
   - Accessible React file picker modal (`FilePickerModal.tsx`) with keyboard navigation, project root notice, file size formatting, and automatic disablement of files exceeding 50MB.

3. **Chat Exploration Safety (No Accidental Task Creation)**:
   - Exploration remains pure interactive chat until the operator explicitly triggers promotion.
   - Adding chat messages, streaming tokens, or attaching reference documents creates **zero** tasks in `TaskService`.
   - Explicit promotion modal ("⚡ Promote to Task") captures task description, target agent role, git branch, complexity (`low`, `medium`, `high`), and selected attachments.

4. **Explicit Task Promotion to Server-Side Queue**:
   - `POST /api/v1/conversations/:id/promote` delegates to `conversationService.promoteToTask()`.
   - Creates a tracked server-side `Task` in `TaskService` with assigned agent, complexity, and requirement specifications.
   - Idempotency-key support ensures network retries do not create duplicate tasks.
   - Updates the conversation entity to link `taskId` directly to the resulting task.

5. **Task Feed Home with Dual-Pane Layout**:
   - Left pane: Interactive task feed table showing ID, description, assigned agent, status badge (`PENDING`, `ACTIVE`, `DONE`, `FAILED`), and complexity. Includes filter dropdowns for status and agent.
   - Right pane: Task Inspector detail panel showing full requirements, git branch, timestamps, and active status.
   - **Offline Queue Persistence Guarantee**: Tasks run on the background server queue. Closing, refreshing, or disconnecting the browser window does not interrupt task execution.
   - Role panel adaptivity reflecting the active `RolePreset` (Developer, Inspector/Analyst, Architect, Manager/Reviewer).

6. **4-Way Interface Parity**:
   - Full interface parity across ServiceContainer (`services.conversation`, `services.task`), REST API router (`/api/v1/conversations`, `/api/v1/project/files`), `BrowserRestClient`, and `GuiApiAdapter`.

## Architecture & Data Flow

```text
Operator in Browser (GUI)
  │
  ├─ ChatView.tsx (Multi-session tabs, exploration thread, attachments)
  │    │
  │    ├─ [Safe File Picker] ──► GET /api/v1/project/files
  │    │                           │
  │    │                           └─► Traversal check & filter .maos/.git
  │    │
  │    ├─ [Send Message] ──────► POST /api/v1/conversations/:id/messages
  │    │                           │ (Atomic write to .maos/conversations/)
  │    │                           └─ Zero task created (Pure chat)
  │    │
  │    └─ [Promote to Task] ──► POST /api/v1/conversations/:id/promote
  │                                │
  │                                ├─► TaskService.createTask() (Persistent server queue)
  │                                └─► Updates conversation.taskId
  │
  └─ TasksView.tsx (Dual-pane Task Feed + Task Inspector)
       │
       ├─ [Task Feed Table] ───► GET /api/v1/tasks
       │                           │
       │                           └─► Survives UI disconnects / background execution
       │
       └─ [Task Inspector] ────► Displays agent, requirements, branch, and status
```
