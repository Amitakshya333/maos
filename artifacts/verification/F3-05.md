## 1. Architectural Summary

F3-05 implements the Safe Artifact Store in `ArtifactService`, enforcing atomic, tamper-evident, and strictly project-confined artifact production and retrieval.

```
Caller (Task Runner, Agent, CLI, GUI, REST API)
                      │
                      ▼
 1. validate project-relative path, containment, type, size, symlinks
                      │
                      ▼
 2. collision & duplicate check (unapproved overwrite rejected)
                      │
                      ▼
 3. create unique temporary file in .tmp/
                      │
                      ▼
 4. write bytes → flush → close → fsync
                      │
                      ▼
 5. validate content / JSON formatting
                      │
                      ▼
 6. compute Rust-backed SHA-256 hash (authoritative verification)
                      │
                      ▼
 7. verify expected hash if supplied (mismatch aborts & unlinks)
                      │
                      ▼
 8. atomically rename temporary file to final path (fs.renameSync)
                      │
                      ▼
 9. persist metadata in .maos/artifacts/metadata/<id>.json
                      │
                      ▼
10. append ARTIFACT_FINALIZED event to event store
```

### Invariants Enforced

1. **Mandatory Finalization Pipeline Order**:
   - Temporary file creation, write, flush, close, and `fsync` occur before hash computation and validation.
   - Atomic rename (`fs.renameSync`) occurs before event emission.
   - If any step fails before atomic rename, the temporary file is unlinked, no metadata record is created, and NO event is emitted.

2. **Zero Phantom Successes**:
   - In complete or interrupted writes, invalid content, hash mismatch, or unapproved overwrite, the event store is never touched and no phantom success event is emitted.

3. **Collision & Duplicate Finalization Protection**:
   - If destination file already exists or artifact ID is already recorded, the operation fails with `ARTIFACT_COLLISION` or `DUPLICATE_FINALIZATION`.
   - Silent overwrites are impossible. Overwrite strictly requires `allowOverwrite: true` and an approved `approvalId` verified through `ApprovalService`.

4. **Project-Root Confinement & Symlink Escapes**:
   - Relative paths containing `..` or absolute paths outside the project root fail closed with `PATH_TRAVERSAL` or `PATH_OUTSIDE_PROJECT`.
   - Symlinks pointing outside `projectRoot` are detected via `fs.realpathSync` and rejected with `SYMLINK_ESCAPE`.

5. **Authoritative Rust-Backed Hashing**:
   - Rust engine executable at `rust/target/release/maos-engine.exe` is verified and invoked via `rust-engine-bridge`.
   - If the Rust engine is tampered or fails, `RUST_HASH_FAILED` is thrown, aborting finalization.
   - Expected hash matching ensures tamper detection before placing the artifact.

6. **Temporary File Invisibility & Cleanup**:
   - `listArtifacts()` and `getArtifact()` ignore `.tmp` files.
   - `cleanupOrphanTempFiles()` purges orphaned temporary files left by system crashes or write interruptions during startup or on demand.

7. **REST Integration**:
   - Mounted `POST /api/v1/artifacts` in `RestApiRouter` and documented in OpenAPI 3.1.0 specification.
