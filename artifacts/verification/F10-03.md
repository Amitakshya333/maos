# Phase F10-03 Verification: Expose Typed Workflow Projections to Clients

## 1. Overview & Requirements
- **Goal:** Finalize and verify typed workflow projections for clients (state, dependencies, tool, retry, review, model, timing, artifacts, routes).
- **Specification:**
  - Scope: Complete projection payload covering all 9 required fields:
    1. `state`: Runtime-derived stage node status (`PENDING`, `READY`, `RUNNING`, `COMPLETED`, `FAILED`, `WAITING_APPROVAL`, `INTERRUPTED`).
    2. `dependencies`: Upstream prerequisite step IDs.
    3. `tools`: Accumulated tool invocations with status, invocation count, and execution durations.
    4. `retries`: Execution retry counter, max limits, and retry reasons.
    5. `review`: Human approval gate status, scope, approver, and reviewer notes.
    6. `model`: Pinned inference model metadata (modelId, family, git revision, device, CPU fallback).
    7. `timing`: Telemetry latency and token counts (prompt, completion, total, latencyMs, startedAt, completedAt).
    8. `artifacts`: Staged input source IDs, generated artifact IDs, hashes, and schemas.
    9. `routes`: Canonical client API routes for stage, approval, artifact downloads, replay, stop, audit.
  - Acceptance: Projections are purely runtime-derived from domain state; static placeholders or synthetic raw log parsing are strictly forbidden.
- **Canary Hash Preservation:** `rust/test.txt` SHA-256 = `1392245502333919f23e58b8f544f12470db3829aabd5336a011e58d2b733435`.

## 2. Implementation Summary

### A. Domain Projection Types & Reducer Logic (`src/domain/cockpit.ts`)
1. **Added Typed Projection Schemas:**
   - `CockpitStageRoutes`: Canonical URI map (`stage`, `approval`, `artifacts`).
   - `CockpitStateRoutes`: Canonical URI map (`run`, `replay`, `stop`, `stages`, `approvals`, `audit`).
   - `WorkflowProjection`: Single stage projection capturing all 9 required fields.
   - `WorkflowRunProjection`: Full DAG run projection with stages, dependencies, timing, tokens, and routes.
2. **Pure Projection Functions:**
   - `projectStageNode(node, projectId, runId)`: Pure function transforming internal `CockpitStageNode` to typed `WorkflowProjection`.
   - `projectWorkflowState(state)`: Pure function transforming `CockpitState` to typed `WorkflowRunProjection`.
   - `projectWorkflowStage(stage, projectId)`: Pure function transforming `WorkflowStage` from `WorkflowService` into `WorkflowProjection`.
3. **Event-driven Reducer Enhancements:**
   - Supported `event.stepId` and `event.agentId` at both root event and payload levels.
   - Handled `TOOL_INVOKED` and `TOOL_EXECUTION` for tool telemetry updates.
   - Handled `STAGE_COMPLETED` and `STEP_COMPLETED` with prompt/completion/total tokens and latency deltas.
   - Handled `STAGE_INTERRUPTED` and `STEP_INTERRUPTED` preventing phantom completions.

### B. Service Container Integration
1. **`WorkflowService` (`src/service/workflow-service.ts`):**
   - Added `getWorkflowProjection(stageId: string, projectId?: string): WorkflowProjection | null`.
2. **`CockpitService` (`src/service/cockpit-service.ts`):**
   - Added `getWorkflowRunProjection(projectId: string, runId: string): WorkflowRunProjection | null`.

### C. REST API Router Mounting (`src/api/router.ts`)
1. `GET /api/v1/workflows/runs/:runId/stages`: Returns all stages in a run.
2. `GET /api/v1/workflows/:id/projection`: Returns `WorkflowProjection` for a stage.
3. `GET /api/v1/runs/:id/projection` & `GET /api/v1/cockpit/:id/projection`: Returns `WorkflowRunProjection`.

### D. GUI Client & Adapter (`src/gui/src/api/rest-client.ts` & `src/gui/src/api/adapter.ts`)
1. `BrowserRestClient.getWorkflowProjection(stageId)`
2. `BrowserRestClient.getWorkflowRunProjection(runId, projectId)`
3. `GuiApiAdapter.getWorkflowProjection(stageId)`
4. `GuiApiAdapter.getWorkflowRunProjection(runId, projectId)`
