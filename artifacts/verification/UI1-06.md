## Executive Summary

Task **UI1-06** has been implemented, validated, and fully verified. It establishes end-to-end browser and local server security hardening for the MAOS industrial desktop environment:

1. **Content Security Policy (CSP)**: Served dynamically by the local HTTP server on all REST API and SPA asset responses, matching the exact sovereign desktop policy.
2. **Mandatory Browser Security Headers**: All responses deliver `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`, `X-Frame-Options: DENY`, `Permissions-Policy`, and `Cache-Control: no-store` (with immutable caching reserved strictly for hashed static assets).
3. **Zero Wildcard CORS**: All occurrences of `Access-Control-Allow-Origin: *` have been permanently eliminated across the entire codebase. Only validated loopback origins are echoed.
4. **Strict URL Token Hygiene**: Any attempt to pass authentication tokens or credentials in URL query strings (e.g., `?token=`, `?sessionToken=`, `?authToken=`, `?bearer=`, `?apiKey=`) is immediately rejected with `400 FORBIDDEN_URL_TOKEN` on both REST and WebSocket upgrade endpoints.
5. **Header Sanitization**: `X-Correlation-ID` and `Idempotency-Key` headers are strictly sanitized; any attempt to supply Bearer tokens or credentials inside correlation IDs or idempotency keys is either safely replaced or rejected with `400 INVALID_IDEMPOTENCY_KEY`.
6. **Automatic Error Envelope Redaction**: Error responses automatically pass error messages and details through recursive sensitive data redaction, ensuring `Authorization` headers, Bearer tokens, private keys, and API secrets are never returned in error envelopes.
7. **Zero Storage Footprint**: Session tokens are strictly stored in-memory (`SessionManager` on the backend, private instance state in frontend clients). Zero tokens are written to `localStorage`, `sessionStorage`, `IndexedDB`, `.maos/status/service-identity.json`, or global recent-project metadata.
8. **WebSocket Subprotocol Negotiation**: Browser WebSocket clients pass tokens exclusively via `Sec-WebSocket-Protocol: ['maos-v1', 'maos-auth.<token>']`. The server verifies the token and responds with `Sec-WebSocket-Protocol: maos-v1`, redacting the auth subprotocol from the handshake response.
9. **Offline Bundle Hygiene**: The production bundle in `dist/gui` was verified to contain zero external font references (e.g. Google Fonts), zero CDN script references, and zero `eval()`.

## Detailed Security Controls

### 1. Canonical Content Security Policy (`security-headers.ts`)

The canonical policy served across all endpoints:

```text
default-src 'self';
script-src 'self';
style-src 'self' 'unsafe-inline';
img-src 'self' data:;
font-src 'self';
connect-src 'self' http://127.0.0.1:* http://[::1]:* ws://127.0.0.1:* ws://[::1]:*;
object-src 'none';
base-uri 'none';
frame-ancestors 'none';
form-action 'self';
manifest-src 'self';
worker-src 'self';
```

#### Scoped CSP Exception Rationale
- **`style-src 'self' 'unsafe-inline'`**: Required by React runtime components for dynamic layout computation and active theme variable styling.
- **`script-src 'self'`**: Strictly locked down with **NO** `'unsafe-inline'`, **NO** `'unsafe-eval'`, and **NO** remote script CDNs.

---

### 2. Browser Security Headers Dictionary

Exported from `src/api/security-headers.ts` and delivered on all responses:

| Header | Value | Purpose |
|---|---|---|
| `Content-Security-Policy` | Full sovereign policy | Restricts scripts, styles, objects, connections |
| `X-Content-Type-Options` | `nosniff` | Prevents MIME-type confusion attacks |
| `Referrer-Policy` | `no-referrer` | Prevents token or path leakage in referrer headers |
| `X-Frame-Options` | `DENY` | Anti-clickjacking protection |
| `Permissions-Policy` | `accelerometer=(), camera=(), geolocation=(), gyroscope=(), magnetometer=(), microphone=(), payment=(), usb=()` | Blocks access to hardware sensors and non-essential APIs |
| `Cache-Control` | `no-store` | Prevents caching of authenticated and dynamic payloads |

---

### 3. Elimination of Wildcard CORS

- **Audited**: All occurrences of `'Access-Control-Allow-Origin': '*'` were removed from `src/cli/dashboard.ts` and replaced with `getLegacyCorsHeaders(req)`.
- **Validation**: Incoming requests with `Origin` headers are validated against loopback hosts (`127.0.0.1`, `localhost`, `::1`). External origins, `file://`, `Origin: null`, and non-loopback LAN IPs are rejected with `403 FORBIDDEN_ORIGIN`.
- **Echo Policy**: Validated loopback origins are echoed back verbatim (`res.setHeader('Access-Control-Allow-Origin', trimmedOrigin)`), paired with `Vary: Origin`.
