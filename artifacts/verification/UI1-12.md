## Executive Summary

Task **UI1-12** implements a fair, cancellable execution queue that coordinates execution requests and model lease acquisition across interactive chat, user tasks, active/auto workflows, and background indexing:

1. **Fixed Priority Classes & Effective Priority Ordering**:
   - 5 explicit priority classes: `interactive_chat` (weight 1), `user_task` (weight 2), `active_workflow` (weight 3), `auto_workflow` (weight 4), `background_indexing` (weight 5).
   - Higher priority (lower numerical value) requests are dispatched first.

2. **FIFO Tie-Breaking**:
   - Requests with equal effective priority and age strictly follow FIFO enqueue order (`enqueuedAt` ascending).

3. **60-Second Aging Anti-Starvation**:
   - Once a request has waited $\ge 60$ seconds in queue, its effective priority improves by 1 class.
   - Promotion is capped at priority class 2 (`user_task`) so that background or workflow tasks can never preempt fresh interactive chat bursts.

4. **Chat Burst Fairness Limit (3 Consecutive Turns)**:
   - Interactive chat turns are tracked with a consecutive turn counter.
   - When consecutive chat turns reach 3, the scheduler yields priority to pending workflow and background tasks, preventing interactive chat from starving longer-running jobs.

5. **Explicit 9 Queue State Transitions**:
   - `queued` $\to$ `waiting_for_model_lease` / `waiting_for_vram` $\to$ `running` $\to$ `cancelling` $\to$ `cancelled` / `completed` / `failed` / `interrupted`.

6. **Safe Cancellation & Phantom Success Defense**:
   - Queued requests transition immediately to `cancelled` with queue position 0.
   - Running requests trigger abort controller signal cancellation and release active model leases immediately.
   - Phantom success defense: attempts to report completion on cancelled or interrupted tasks throw `CANNOT_COMPLETE_CANCELLED_TASK` (400).

7. **VRAM Queue-First Residency & Explicit CPU Fallback**:
   - When GPU VRAM is occupied by another model, GPU requests enter state `waiting_for_vram` rather than evicting resident weights or crashing.
   - CPU fallback occurs only when `allowCpuFallback: true` is explicitly permitted by the request.

8. **Dependency Gating**:
   - Requests with dependencies remain in queue with `blockingReason` until parent dependencies reach state `completed`.

9. **Service Restart Recovery**:
   - `recoverQueueState()` scans the queue on service reboot, transitions stranded `running` or `cancelling` tasks to `interrupted`, releases any dangling model leases, and logs `QUEUE_RECOVERED`.

10. **Project & Run Boundary Isolation**:
    - Cross-project cancellation is forbidden and rejected with `CROSS_PROJECT_CANCELLATION_FORBIDDEN` (403).
    - Releasing or cancelling a run-scoped entry with mismatched `runId` is rejected with `WRONG_RUN_CANCELLATION_FORBIDDEN` (403).

11. **Tamper-Evident Audit Logging**:
    - Every queue transition generates structured audit records via `AuditService`:
      - `QUEUE_ENQUEUED`
      - `QUEUE_STARTED`
      - `QUEUE_CANCELLED`
      - `QUEUE_COMPLETED`
      - `QUEUE_FAILED`
      - `QUEUE_RECOVERED`

12. **Full GUI Cockpit (`ModelsView.tsx` & `TasksView.tsx`)**:
    - Real-time Queue Metrics widget bar: Queued/Waiting, Active Running, Waiting for VRAM, and Consecutive Chat Turns progress ($X/3$).
    - Interactive Queue Table rendering all 9 typed states, priority badges, aging tags, model/device requirements, age in seconds, blocking reasons, and Cancel buttons.
    - Recover Stranded Tasks trigger button.
    - Tasks & Workflow feed links directly to the Queue Cockpit.

13. **4-Way Client Parity**:
    - `ServiceContainer` $\to$ `RestApiRouter` $\to$ `MaosRestClient` $\to$ `BrowserRestClient` $\to$ `GuiApiAdapter`.
