## 2. Implemented Subsystems

### 2.1 Durable Idempotency Store (`src/core/idempotency-store.ts`)
- **Disk Persistence:** Records stored in `.maos/idempotency/<keyHash>.json` with durable `fsync`.
- **Atomic Exclusive Claim:** Employs exclusive creation (`'wx'` flag) to atomically claim idempotency keys.
- **Concurrent Lockout:** When a request is in flight (`status: 'in_progress'`), duplicate claims are rejected with `409 CONCURRENT_MUTATION`.
- **Faithful Replay:** Subsequent identical requests return the cached HTTP status code and response payload with header `Idempotent-Replay: true`.
- **Conflict Detection:** Identical key with differing request payload SHA-256 returns `409 IDEMPOTENCY_CONFLICT`.
- **Authorization Scoping:** Caller authorization context (`Authorization` header) is hashed and checked against prior claims; mismatch returns `403 AUTHORIZATION_MISMATCH`.
- **Crash & Restart Recovery:** Survives process restart by reloading completed records from disk. Stale in-progress locks (> 30s) are automatically reclaimed.

### 2.2 Canonical Domain Verifier (`src/service/verifier-service.ts`)
- `verifySchemaVersion`: Enforces explicit `schemaVersion: 1` across all domain payloads.
- `verifyRelationship`: Validates hierarchical scoping (Project -> Task -> Run -> Artifact) and fails closed on cross-project leaks.
- `verifyArtifact`: Validates physical existence, project-root confinement, and recalculates authoritative SHA-256 against stored metadata to detect file tampering.
- `verifyModel`: Validates model identity, revision, and file hashes against `model-snapshot-manifest.json`.
- `verifyServiceIdentity`: Validates service manifests and executable hashes against registered industrial services.
- `verifyAuditReference`: Validates sequence references and verifies the entire cryptographic hash chain via the Rust engine (`maos-engine.exe`).
- `verifyEventSequence`: Validates event stream monotonicity and sequence retention bounds.
- `verifyApproval`: Validates approval gate existence, gateId, and resolution status.
- `verifyRequestResponse`: Validates cryptographic SHA-256 hashes of incoming request bodies and outgoing response payloads.
- `verifyRun`: Executes comprehensive end-to-end run verification across stages, tasks, artifacts, sequenced events, and audit logs.

### 2.3 Verification REST APIs (`src/api/router.ts`)
Exposes typed verification endpoints consumed by CLI and the future GUI client:
- `POST /api/v1/verify/run`
- `POST /api/v1/verify/artifact`
- `POST /api/v1/verify/model`
- `POST /api/v1/verify/audit`
- `POST /api/v1/verify/relationship`
- `POST /api/v1/verify/service`

All mutation routes (`/api/v1/tasks`, `/api/v1/conversations`, `/api/v1/workflows`, `/api/v1/approvals`, `/api/v1/artifacts`, `/api/v1/models/leases`, `/api/v1/events`, `/api/v1/audit/events`) now pass through the `DurableIdempotencyStore`.
