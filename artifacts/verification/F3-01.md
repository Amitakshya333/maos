## Architectural Summary

F3-01 establishes the application service boundary for MAOS. Prior to this task, business logic was intertwined with presentation in CLI handlers and dashboard endpoints. All business capabilities are now encapsulated in typed, presentation-agnostic application services under `src/service/`.

```
CLI adapter  ─────┐
Dashboard adapter ─┤──→ Typed Application Services ──→ Policy / Tool / Orchestrator
Future React GUI ──┤    (src/service/*)
Future Tauri shell ┘
```

### Strict Architectural Invariants Enforced

1. **Adapter Separation**: Both CLI and Web/GUI adapters consume the same typed application services.
2. **No Subprocess Shelling**: The GUI/dashboard never shells out to the CLI (`GUI → shell → CLI` is forbidden).
3. **Clean Presentation Boundary**:
   - `0` imports of `chalk` in `src/service/`
   - `0` imports of `commander` in `src/service/`
   - `0` calls to `process.exit()` in `src/service/`
   - `0` imports from `src/cli/` in `src/service/`
4. **Shared Project Context**: All services are instantiated via `createServiceContainer(projectRoot)` sharing a canonical project root directory.

## Extracted Application Services

| Service | File | Responsibilities | Extracted From |
|---|---|---|---|
| `ProjectService` | `src/service/project-service.ts` | Config loading, profile detection (`isIndustrialProfile`), provider enumeration, agent inventory, initialization check | `cli/init.ts`, `cli/configure.ts`, `core/orchestrator.ts` |
| `TaskService` | `src/service/task-service.ts` | Task creation, queue queries (`pending`, `active`, `done`), queue counts, atomic queue cleanup (`clean`) | `cli/task.ts`, `cli/status.ts`, `cli/index.ts` (clean), `core/queue.ts` |
| `WorkflowService` | `src/service/workflow-service.ts` | High-level objective lifecycle (create, load, list), multi-agent decomposition plans | `cli/objective.ts`, `cli/plan.ts`, `core/objective-store.ts` |
| `OrchestrationService` | `src/service/orchestration-service.ts` | Orchestrator startup, execution lifecycle, live status update hooks, running state tracking | `cli/start.ts`, `core/orchestrator.ts` |
| `EventService` | `src/service/event-service.ts` | Event log queries, task timeline summaries, full task replay as typed `AuditEvent[]`, event stats | `cli/index.ts` (replay), `core/event-store.ts` |
| `MemoryService` | `src/service/memory-service.ts` | Inter-agent knowledge sharing, content/tag search, live memory queries, memory clearing/archival | `cli/index.ts` (memory), `core/context-memory.ts` |
| `HealthService` | `src/service/health-service.ts` | Agent pool management (enable/disable), agent status inspection, retry queue, dead-letter queue queries | `cli/pool.ts`, `cli/doctor.ts`, `core/retry-queue.ts` |
| `ModelService` | `src/service/model-service.ts` | Model discovery, credential validation for local and cloud providers | `backends/factory.ts`, `core/credentials.ts` |
| `ServiceContainer` | `src/service/index.ts` | Factory `createServiceContainer(projectRoot)` bundling all 8 services into a single unified container | Unified entry point |

## Refactored Adapters

The following CLI handlers have been refactored to be thin adapters over `createServiceContainer`:

| Adapter | Refactored Operations |
|---|---|
| `src/cli/index.ts` | `maos clean` → `services.task.clean()`; `maos queue` → `services.health.getRetryQueueStatus()` & `getDeadLetterQueue()`; `maos replay` → `services.event.getStats()`, `getTaskTimelineSummary()`, `query()`; `maos memory` → `services.memory.clear()`, `getStats()`, `search()`, `searchByTag()`, `getLive()` |
| `src/cli/task.ts` | `runTask()` → `services.project.isInitialized()`, `services.task.createTask()` |
| `src/cli/status.ts` | `runStatus()` → `services.project.isInitialized()`, `getAgents()`, `services.health.getAgentPool()`, `services.task.getQueueCounts()`, `listTasks()` |
| `src/cli/start.ts` | `runStart()` → `services.project.isInitialized()`, `loadConfig()`, `services.task.getQueueCounts()`, `services.orchestration.start()` |
| `src/cli/plan.ts` | `runPlan()` → `services.project.isInitialized()`, `loadConfig()`, `services.task.createTask()` |
