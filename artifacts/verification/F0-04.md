## Residency Policy

### Frozen Rules

1. **One model at a time.** The shared GPU Model Manager loads exactly one model into VRAM. Concurrent GPU model loading is disabled because no 3B model pair fits within 8 GB.

2. **Serialized inference.** All inference requests are serialized through a single model endpoint. No concurrent model inference is permitted. This is a hardware-manifest-driven decision, not a configuration default.

3. **Cold load budget.** Based on existing P4-04 measurement, CPU-mode cold load takes ~175s. GPU cold load is expected at ~15-30s for a 3B model. Three cold starts must complete without OOM — this is feasible with serialized loading since each load uses ~6 GB of 8 GB available.

4. **Model unload on idle.** Default: 3 minutes after last inference request. Configurable per project. Unload frees VRAM for the next model.

5. **Service idle grace.** Default: 10 minutes after last user activity. Active tasks keep the service alive regardless.

### Queue Priority (frozen)

| Priority | Class | Example |
|---|---|---|
| 1 (highest) | Interactive chat | User typing in chat panel |
| 2 | User-requested task | User explicitly triggers an analysis |
| 3 | Active workflow stage | Running DAG stage already in progress |
| 4 | Automatic workflow stage | Next stage in a DAG awaiting model |
| 5 (lowest) | Background indexing | KB re-indexing, embedding generation |

### Anti-Starvation

- Aging: after 60 seconds in queue, a request's effective priority increases by one level (capped at priority 2).
- Reservation: an active workflow may reserve the next model load to avoid thrashing between chat and workflow.
- Fair limit: interactive chat cannot starve a workflow for more than 3 consecutive turns.

### Model Switching

| Context | Policy |
|---|---|
| Between chat turns | User may switch model freely |
| Within a workflow run | Model is fixed for the entire run (frozen at DAG creation) |
| Manual override | Available and audited; applies to next request only |
| Silent switch | ❌ Forbidden — every model change is visible and logged |

### VRAM Pressure

| Action | Order |
|---|---|
| 1 | Queue the request (default) |
| 2 | Offer explicit CPU fallback (user must confirm) |
| 3 | Never silently switch device or model |

### CPU Fallback

- Available but must be explicitly enabled in project settings.
- CPU inference is ~10x slower (measured ~175s/turn for 3B model).
- GUI must show "Running on CPU" prominently when active.
- Suitable only for demo with preloaded evidence or non-interactive tasks.

## Verified: Three Cold Starts Without OOM

With serialized loading on 8 GB VRAM:
1. Load text model (~6 GB) → unload → ✅
2. Load coder model (~6 GB) → unload → ✅  
3. Load vision model (~7 GB) → unload → ✅ (tight but within 8 GB)

No concurrent loads means no OOM risk. Each model has ~1-2 GB headroom.
