## Architectural Deliverables & Controls

### 1. Tool Definition & Registration (`src/integrations/tools.ts`)
- Registered `execute_code_sandbox` in `AGENT_TOOLS` with typed schema:
  - `script` (string, required): Python source code to execute.
  - `args` (string[], optional): Command-line arguments.
  - `files` (record, optional): Map of relative filenames to string contents staged in `/sandbox/workspace`.
  - `timeoutMs` (number, optional): Hard execution timeout (max 30,000ms).
  - `maxOutputBytes` (number, optional): Output buffer byte limit (max 50,000 bytes).
  - `projectId` (string, optional): Active project identifier.
  - `requestId` (string, optional): Unique idempotency request identifier.
  - `approvalId` (string, optional): Optional authorization reference.
- Parameter boundaries and traversal attacks are rejected before spawning containers.

### 2. Dual Synchronous & Asynchronous Parity
- **Synchronous Execution Gateway (`executeCodeSandboxTool`)**:
  - Leverages `ContainerRunner.runSync()` backed by `child_process.spawnSync`.
  - Integrates seamlessly with `executeTool()` in `src/core/agent-runner.ts` without event loop blocking bugs or synthetic delays.
- **Asynchronous Execution Gateway (`executeCodeSandboxToolAsync`)**:
  - Leverages `SandboxRunnerService.execute()` for REST API and background job consumers.
  - 100% parity: produces identical output, exit codes, input/output canonical hashes, and staged files.

### 3. Agent Role Authorization & Tool Filtering
- Authorized agents in `AUTHORIZED_CODE_SANDBOX_AGENTS`:
  - `coder_agent`, `coder`, `analyst_agent`, `analyst`, `code_agent`, `lead-inspector`, `inspector`, `supervisor_agent`, `supervisor`, `test-agent`, `verification`, `admin`.
- Dynamic filtering via `getToolsForAgent(allowedTools, agentId)`:
  - Authorized agents receive `execute_code_sandbox`.
  - Unauthorized agents (`random_bot`, `guest`, `sales_agent`) are strictly filtered out.
  - Explicit `allowedTools` lists are strictly respected.
  - Direct invocations without authorization fail closed with `UNAUTHORIZED_AGENT`.

### 4. Tool Approval Planning Integration (`src/industrial/tool-approval-planner.ts`)
- Added `execute_code_sandbox` to `primaryDomainTools` in `resolvePrincipalTool()`.
- Deterministic contract creation:
  - Steps with `safetyCritical: true` automatically derive `SAFETY_CRITICAL_APPROVAL_REQUIRED` with human review gate and required `safety-officer` sign-off.
  - Steps with `requiresApproval: true` derive `EXPLICIT_APPROVAL_REQUIRED` with required `supervisor` sign-off.
  - Standard sandboxed calculation steps derive `NO_APPROVAL_REQUIRED`.
- Multi-surface prompt injection defense:
  - Detects and rejects adversarial instructions attempting to bypass approvals (`skip approval`, `override approval`) with `PROMPT_INJECTION_REJECTED`.
  - Detects and rejects attempts to escalate tool privileges (`run bash instead`, `elevate tool`) with `PROMPT_INJECTION_REJECTED`.

### 5. Durable Idempotency & Privacy-Preserving Audit Trail
- Repeated requests with identical `requestId` replay cached results without spawning redundant containers.
- Concurrent conflicting requests with altered payloads fail closed with `IDEMPOTENCY_CONFLICT`.
- Every tool execution emits an immutable audit event to `AuditService` with `source: 'sandbox-runner'`, canonical input hash, canonical output hash, duration, container name, exit status, and zero leaked source code or secrets.
