## REST API Specification

### 1. `GET /api/v1/layout`
- **Query Parameters**:
  - `role` (optional): Fallback role preset if uninitialized (default: `developer`)
  - `projectId` (optional): Project ID override (default: canonical project ID)
- **Response**: `200 OK`
  ```json
  {
    "data": {
      "schemaVersion": 1,
      "projectId": "proj_alpha_12345",
      "role": "developer",
      "pinnedModules": ["chat", "tasks", "code", "terminal", "cockpit"],
      "collapsedModules": ["evidence", "documents", "knowledge", "audit"],
      "activeModule": "chat",
      "drawerOpen": true,
      "sidebarWidth": 240,
      "drawerHeight": 220,
      "updatedAt": "2026-09-17T12:45:00.000Z"
    },
    "exists": true
  }
  ```

### 2. `PUT /api/v1/layout`
- **Request Body**: `WorkspaceLayout`
- **Validates**: `schemaVersion: 1`, valid role preset, valid module IDs, clamps dimensions.
- **Response**: `200 OK` with updated `WorkspaceLayout`.
- **Errors**: `400 INVALID_WORKSPACE_LAYOUT` if validation fails.

### 3. `POST /api/v1/layout/reset`
- **Request Body**: `{ "role": "developer" }` (optional)
- **Action**: Resets layout to the canonical role preset default and persists to disk.
- **Response**: `200 OK` with reset `WorkspaceLayout`.

The test suite explicitly verifies the safety invariants:
1. **Tool Permissions**: Changing the role to `manager_reviewer` or `developer` does not grant access to privileged or restricted tools without backend authorization.
2. **Approval Gates**: Resolving approvals without an authenticated session fails closed (`401 UNAUTHORIZED`) regardless of active UI role preset.
3. **Project Confinement**: Cross-project path traversal or header spoofing (`X-Project-Root`) fails closed (`400 PROJECT_SCOPE_MISMATCH` or `403 FORBIDDEN_PROJECT_SCOPE`).
4. **Audit Immutability**: Rapid role switching does not mutate, disrupt, or corrupt the cryptographic audit verification chain (`/api/v1/audit/verify` remains `valid: true`).
5. **Network Confinement**: Loopback binding (127.0.0.1) and strict Content Security Policy headers are invariant across all role configurations.
