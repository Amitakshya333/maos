## Executive Summary

Task **F7-02** implements the deterministic inference engine and model routing integration for MAOS text and attachment-based requests.

Key capabilities delivered:
1. **Multimodal & Attachment Support**: Accepts text-only, attachment-only, and multimodal inputs.
2. **Deterministic Inference Rules (`INFERENCE_RULES_V1`)**: 18 versioned, prioritized rules that map input characteristics to explicit intents, required modalities, tool constraints, and agent assignments.
3. **100% Output Determinism**: Canonical SHA-256 `inputHash` and strictly ordered priority matching guarantee identical results across repeated evaluations.
4. **Structured Evidence & Traceability**: Returns matched rule IDs, rule versions, confidence scores, reasoning codes, and granular supporting evidence references (preserving artifact names, mimeTypes, and source hashes).
5. **Prompt-Injection Neutralization**: Attachment content is treated strictly as data; malicious instructions embedded within attached files cannot hijack inference rules or redirect tasks.
6. **Ambiguity & Clarification Protocols**: Detects vague, underspecified, or conflicting requests (e.g. asking for multiple office deliverables simultaneously without a pipeline context) and returns structured clarification prompts instead of guessing broadly with an LLM.
7. **Fail-Closed Safety**: Unsupported capabilities (cloud deployment, live web scraping, cryptocurrency mining, air-gap bypass) fail closed with `UNSUPPORTED` status and zero agent assignment.
8. **Non-Degradation Integration (`Router.routeInference`)**: Seamlessly converts `InferenceResult` into `TaskRequirements` and enforces F7-01 non-degradation requirements (e.g. vision tasks fail closed when no vision-capable agent is available).
9. **Privacy-Preserving Audit Trail**: Logs `INFERENCE_EXECUTED` audit events containing status, intent, confidence, and input hash without leaking raw prompt prose or sensitive attachments.

## Architecture & Implementation Details

### 1. Domain Types (`src/domain/inference.ts`)

- `TaskAttachment`: Models file attachments with `name`, `mimeType`, `sourcePath`, `content`, `buffer`, `sourceHash`, `artifactId`, `sizeBytes`, `pageCount`, and `metadata`.
- `InferenceInput`: Unified input container accepting `text`, `attachments`, and optional `context`.
- `InferenceStatus`: `'MATCHED' | 'AMBIGUOUS' | 'UNSUPPORTED' | 'CLARIFICATION_REQUIRED'`.
- `EvidenceReference`: Traceable citation link with `source`, `ref`, `matchDetail`, and optional `hash`.
- `InferenceRule`: Immutable versioned rule definition with `ruleId`, `name`, `version`, `priority`, `category`, `targetIntent`, `requiredModalities`, `suggestedAgent`, `suggestedWorkflow`, `inferredRequirements`, and pure `matcher` function.
- `InferenceResult`: Canonical result object versioned at `schemaVersion: 1`, returning classification, confidence, rule attribution, reasoning codes, evidence references, requirements, selected modality, agent, workflow, clarification prompt, `inputHash`, and `deterministic: true`.

### 2. Domain Validators (`src/domain/validators.ts`)

- `validateInferenceInput(input)`:
  - Validates that at least `text` or `attachments` is provided.
  - Enforces text length limits (`MAX_INFERENCE_TEXT_LENGTH = 100,000`).
  - Enforces attachment array limits (`MAX_INFERENCE_ATTACHMENTS = 50`) and attachment name limits (`MAX_ATTACHMENT_NAME_LENGTH = 500`).
  - Validates attachment properties (`sizeBytes >= 0`, `pageCount >= 0`, valid sourceHash format).
- `validateInferenceResult(result)`:
  - Validates `schemaVersion: 1`.
  - Validates `status` is one of `INFERENCE_STATUSES`.
  - Enforces confidence in range `[0.0, 1.0]`.
  - Enforces reasoning codes array limit (`MAX_REASONING_CODES = 50`).
  - Enforces supporting evidence array limit (`MAX_EVIDENCE_REFERENCES = 100`).
  - Validates embedded `requirements` via `validateExtendedTaskRequirements`.
  - Enforces `deterministic: true`.

### 3. Industrial Rules Registry (`src/industrial/inference-rules.ts`)

`INFERENCE_RULES_V1` defines 18 prioritized rules:
1. `RULE_UNSUPPORTED_DETECT` (Priority 1000): Catches cloud deployments, live scraping, crypto mining, and sandbox bypass attempts (`UNSUPPORTED`).
2. `RULE_AMBIGUOUS_DETECT` (Priority 900): Catches vague prompts ("fix this", "check") and conflicting uncoordinated deliverable requests (`CLARIFICATION_REQUIRED`).
3. `RULE_OCR_DOCUMENT` (Priority 100): Document OCR with explicit keywords and attached PDF/TIFF (`MATCHED`, `vision`, `ocr-specialist`).
4. `RULE_OCR_ATTACHMENT_ONLY` (Priority 95): Passive PDF/TIFF attachment without prompt (`MATCHED`, `vision`, `ocr-specialist`).
5. `RULE_IMAGE_ANALYSIS` (Priority 90): Visual diagram and image analysis with keywords (`MATCHED`, `vision`, `vision-inspector`).
6. `RULE_IMAGE_ATTACHMENT_ONLY` (Priority 85): Passive image attachment (`MATCHED`, `vision`, `vision-inspector`).
7. `RULE_GENERATE_DOCX` (Priority 80): DOCX report creation directive (`MATCHED`, `text`, `office-docx-builder`).
8. `RULE_GENERATE_XLSX` (Priority 80): XLSX calculation spreadsheet directive (`MATCHED`, `text`, `office-xlsx-builder`).
9. `RULE_GENERATE_PPTX` (Priority 80): PPTX slide presentation directive (`MATCHED`, `text`, `office-pptx-builder`).
10. `RULE_OFFICE_ATTACHMENT_ONLY` (Priority 75): Passive OOXML deliverable inspection (`MATCHED`, `text`, `office-reviewer`).
11. `RULE_KB_SEARCH` (Priority 70): Knowledge base query directive (`MATCHED`, `text`, `kb-researcher`).
12. `RULE_KB_INGESTION` (Priority 70): Knowledge base corpus ingestion directive (`MATCHED`, `text`, `kb-curator`).
13. `RULE_CODE_DEVELOPMENT` (Priority 60): Software implementation & refactoring (`MATCHED`, `code`, `coder`).
14. `RULE_CODE_ATTACHMENT_ONLY` (Priority 55): Passive source code attachment (`MATCHED`, `code`, `coder`).
15. `RULE_CODE_REVIEW` (Priority 50): Code and PR review directive (`MATCHED`, `code`, `reviewer`).
16. `RULE_ARCHITECTURE_PLANNING` (Priority 45): System architecture & planning (`MATCHED`, `text`, `architect`).
17. `RULE_VERIFICATION_AUDIT` (Priority 40): Verification & compliance audit (`MATCHED`, `text`, `verifier`).
18. `RULE_GENERAL_TEXT` (Priority 10): General dialogue and text questions (`MATCHED`, `text`, `general-assistant`).

### 4. Inference Service (`src/service/inference-service.ts`)

- `computeCanonicalInputHash(input)`: Sorts attachments by filename and generates a canonical SHA-256 hash over normalized prompt text and attachment metadata.
- `infer(input)`:
  - Validates input schema.
  - Computes canonical `inputHash`.
  - Evaluates rules in descending priority order.
  - Constructs `InferenceResult` with complete provenance, requirements, and evidence citations.
  - Appends privacy-safe `INFERENCE_EXECUTED` audit record.
  - Fails closed to `AMBIGUOUS` with clarification prompt if no rule matches.

### 5. Router Integration (`src/core/router.ts`)

- `routeInference(inference, agents, blacklist)`:
  - Returns `null` immediately if `inference.status !== 'MATCHED'` (preventing uncoordinated scheduling of ambiguous/unsupported tasks).
  - Translates `InferenceResult` to `TaskRequirements`.
  - Enforces `isAgentEligible` with F7-01 non-degradation rules: if a task requires vision, code, or tools, text-only agents are eliminated; if no compliant candidate exists, the router returns `null` (failing closed).

### 6. Service Container Wiring (`src/service/index.ts`)

- Registered `inference: InferenceService` in `ServiceContainer`.
- Initialized with project `AuditService` in `createServiceContainer(projectRoot)`.
- Re-exported `InferenceService`, `InferenceServiceOptions`, and `computeCanonicalInputHash`.
