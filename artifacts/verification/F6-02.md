## Executive Summary

Task **F6-02** implements the `generate_docx` tool and underlying service for producing real, air-gapped, verifiable, editable Office Open XML (`.docx`) approval notes directly from validated `OfficeDocxInput` domain payloads.

All generation is executed 100% locally and offline in pure TypeScript/Node.js using built-in standard libraries (`node:zlib`, `node:crypto`). The implementation requires zero runtime downloads, zero npm packages, zero external fonts or templates, and completely eliminates reliance on Microsoft Word, LibreOffice, headless binaries, or shell automation.

## Architecture & Implementation Summary

### 1. Pure Node.js OOXML Packager & Offline Validator (`src/industrial/office/ooxml-packager.ts`)
- **PKZIP Builder (`buildZipArchive`)**:
  - Implements compliant ZIP format (local file headers `0x04034b50`, central directory headers `0x02014b50`, end of central directory `0x06054b50`).
  - Standard IEEE polynomial CRC-32 (`0xEDB88320`) and Deflate raw compression (`zlib.deflateRawSync`).
  - Strict forward-slash path normalization and UTF-8 encoding.
- **PKZIP Parser (`parseZipArchive`)**:
  - Re-opens, parses central directory records, decompresses Deflate streams (`zlib.inflateRawSync`), and validates CRC-32 and uncompressed sizes.
- **Offline OOXML Validator (`validateDocxPackage`)**:
  - Re-opens the generated package buffer and verifies PK signature.
  - Ensures mandatory OOXML parts exist: `[Content_Types].xml`, `_rels/.rels`, `word/document.xml`.
  - Rejects macro and executable parts (`.bin`, `vbaProject.bin`, `vbaData.xml`, `.exe`, `.dll`, `.bat`, etc.).
  - Rejects external relationships (`TargetMode="External"` and remote URL schemes in relationships).
  - Verifies XML well-formedness of all XML and `.rels` parts.
  - Rejects hyperlinks, remote URLs, and macro/script execution in `word/document.xml`.

### 2. DOCX Generator Service (`src/service/docx-generator-service.ts`)
- **Document Content Layout**:
  - Document Title (Heading 1)
  - Metadata block (Project ID, Run ID, Task ID, Schema Version, Generation Date, Author Name/Role, Model Identity, Input Hash)
  - Decision / Final Verdict banner with PASS / APPROVED styling, approval ID, approver, timestamp, and comments
  - Findings table with category, status badge (`[PASS]`, `[WARNING]`, `[FAIL]`), statement, metric, observed value, threshold value, unit, citations, and reviewer corrections
  - Validated measurements table with numeric value, mandatory unit, tolerance, and citations
  - Verified calculations table with calculation name, formula/method, inputs, result value + unit, and verification method (`rust_engine`, `deterministic_calc`, `human_expert`)
  - Warnings table (code, severity, message, acknowledgment) and system limitations
  - Evidence state summary (OCR confidence, VLM confidence, conflict status, quarantine status, human review record)
  - Cryptographic citations ledger (Citation ID, source path, SHA-256 digest, page/section/chunk location, verified snippet)
  - Segregated model prose blocks prominently styled with safety disclaimers:
    `[UNVERIFIED MODEL PROSE — NOT VERIFIED AGAINST STRUCTURED DATA — REQUIRES HUMAN REVIEW]`
  - Reviewer identity and sign-off ledger (approval ID, approved status, approved by, approved at, payload hash, sign-off identity)
- **Security & Integrity Guardrails**:
  - Project scope containment: rejects inputs when `input.projectId !== params.projectId`.
  - Safe industrial path validation: rejects traversal (`..`), absolute paths, and non-`.docx` extensions.
  - Mandatory approval: requires `input.approval.status === 'approved'`.
  - Anti-tampering: compares approved `payloadHash` against freshly computed canonical hash of the input; rejects if input was modified after approval (`CHANGED_INPUT_AFTER_APPROVAL`).
  - Dynamic disk freshness: verifies cited source files on disk match citation `sourceHash`.
  - Collision prevention: destination collision without `allowOverwrite: true` throws `ARTIFACT_COLLISION`. Overwrite requires explicit approved approval.
  - Durable idempotency: claims requestId through `DurableIdempotencyStore`; replays cached result on identical parameters; rejects conflicting parameters (`IDEMPOTENCY_CONFLICT`).
  - Atomic finalization: writes to temporary file, syncs to disk (`fs.fsyncSync`), computes authoritative SHA-256 hash, and atomically renames into final destination via `ArtifactService.finalizeArtifact`.
  - Privacy-safe audit events: appends `DOCX_GENERATION_STARTED`, `DOCX_GENERATED`, `DOCX_GENERATION_REJECTED`, `DOCX_GENERATION_FAILED` with cryptographic hashes, IDs, and metadata; zero raw prose.
