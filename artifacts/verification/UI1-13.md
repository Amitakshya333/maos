## Executive Summary

Task **UI1-13** implements the authoritative Model Switcher and Auto-Routing interface and service layer that coordinates model selection across interactive chat, manual operator overrides, and automated workflow pipelines:

1. **Automatic Model Routing Engine**:
   - Deterministic routing based on task requirements, modality, complexity, and visual attachments.
   - Modality `'vision'` / `'multimodal'` / visual attachments $\to$ pinned VLM `Qwen/Qwen2-VL-2B-Instruct` (`cuda`, 3072 MB VRAM, 98% confidence).
   - Modality `'embedding'` / `'similarity'` / `'retrieval'` $\to$ pinned CPU MiniLM `sentence-transformers/all-MiniLM-L6-v2` (`cpu`, 0 MB VRAM, 100% confidence).
   - Modality `'text'` / `'code'` / default reasoning $\to$ pinned LLM `Qwen/Qwen2.5-3B-Instruct` (`cuda`, 4096 MB VRAM, 95% confidence).

2. **Audited Manual Model Override**:
   - Enforces mandatory audit metadata: `actor` (e.g. `operator_alice`, `chat_user`) and `reason` (non-empty explanation).
   - Missing actor or reason fails closed with `UNAUDITED_OVERRIDE` (400).
   - Audit events recorded under category `'model'`, source `'model_switch'`, action `'MODEL_SWITCH'` with complete provenance (previous model, target model, revision, device, and lease IDs).

3. **Authoritative Active Model Identity Visibility**:
   - Authoritative identity queried directly from `SharedModelManager` residency:
     - `modelId`, `modelName`, `revision`, `architecture`, `quantization`, `device`, `vramUsedMb`, `vramBudgetMb`, `activeLeases`, `queueLength`, `healthy`, `isWorkflowFixed`, `lockedByRunId`, `supportedModalities`.
   - Exposed via `GET /api/v1/models/active`, client SDKs, and GUI badges.

4. **Workflow-Fixed Model & Revision Protection**:
   - Mid-run model switches are strictly forbidden:
     - When active GPU leases contain a `runId` (identifying a locked workflow run), any switch away from the resident model throws `WORKFLOW_FIXED_MODEL_PROTECTED` (409).
     - When an incoming switch request targets a `runId` that already holds an active lease on a different model, the switch is rejected with `MID_RUN_SWITCH_FORBIDDEN` (409).

5. **Modality Compatibility Matrix**:
   - Rejects incompatible model selections:
     - Selecting text model for vision modality is rejected with `MODALITY_INCOMPATIBLE` (400).
     - Selecting CPU embedding model for generative text/vision is rejected with `MODALITY_INCOMPATIBLE` (400).

6. **Queue-Aware Switching & Concurrency Violation Protection**:
   - If active GPU leases exist on the current resident model, manual model switch throws `CONCURRENCY_VIOLATION` (409) to preserve ongoing execution leases.
   - Queue requests wait for VRAM (`waiting_for_vram`) via `SharedModelManager` and `FairQueueService` without silent eviction or silent CPU fallback.

7. **Disruptive Switch Confirmation**:
   - Switching between GPU models when 0 leases are active requires unloading the resident model from VRAM.
   - If `confirmed !== true`, the service returns status `CONFIRMATION_REQUIRED` with a warning message (`Switching requires unloading resident model ...`).
   - When `confirmed === true`, unloads old model weights and loads/claims residency on target model.

8. **CPU Model Non-Disruptive Coexistence**:
   - Switching to the CPU embedding model (`all-MiniLM-L6-v2`) requires zero VRAM and does not unload resident GPU models from VRAM.

9. **Zero Runtime Downloads & Snapshot Integrity**:
   - Rejects unregistered models with `MODEL_UNAVAILABLE` (404).
   - Rejects revision mismatches with `REVISION_MISMATCH` (400).
   - Rejects models with missing offline snapshot manifests or directories with `NO_RUNTIME_DOWNLOAD` (400).
   - Rejects unhealthy models with `MODEL_UNHEALTHY` (503).

10. **Interactive GUI Model Switchers**:
    - **Models View Cockpit (`ModelsView.tsx`)**:
      - Active Model Identity card with real-time status and workflow lock badge.
      - Auto-Routing evaluation tool with interactive preview and confidence scores.
      - Audited Manual Override card with target model select, actor, reason, disruptive confirmation checkbox, and execute button.
      - Confirmation modal banner for disruptive model unloads.
    - **Chat View Integration (`ChatView.tsx`)**:
      - Dynamic active model badge in chat thread header (`CUDA: Qwen2.5-3B-Instruct`).
      - In-chat Model Selector dropdown for selecting registered models.
      - In-chat confirmation prompt banner for disruptive unloads.
      - In-chat error alert banner for blocked switches (e.g. workflow-fixed or lease conflicts).

11. **4-Way Parity**:
    - `ServiceContainer` $\to$ `RestApiRouter` $\to$ `MaosRestClient` $\to$ `BrowserRestClient` $\to$ `GuiApiAdapter`.
